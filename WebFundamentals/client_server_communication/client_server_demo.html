📊 HTTP Status Codes & Interview Screeners

Concept: Status codes are 3-digit standard HTTP response codes indicating outcome. Interviewers test your understanding of 2xx success, 3xx caching/redirects, 4xx client errors, and 5xx server gateway errors.
Like train announcements: 200 = on time, 204 = completed with no luggage, 304 = unchanged schedule (check board), 401 = no ticket, 403 = wrong class coach, 429 = queue full, 502/504 = track signal system failure.

🎯 Interactive Demo: Comprehensive Status Code Explorer

Code Category Name Real-World Meaning & Interview Context Action
200 2xx Success OK Standard success response for GET, PUT, or POST returning data.
201 2xx Success Created New resource successfully created (e.g., POST /api/users). Often returns new object + Location header.
204 2xx Success 🔥 Interview Screener No Content Request succeeded, but server intentionally returns NO body payload (common for DELETE or PUT updates).
301 3xx Redirection Moved Permanently Resource URL permanently changed. Browsers automatically cache and redirect future requests to the new location.
304 3xx Redirection 🔥 Interview Screener Not Modified Conditional GET (ETag / If-None-Match) match. Tells browser resource hasn't changed; use cached version (saves bandwidth).
400 4xx Client Error Bad Request Client payload error (malformed JSON syntax, invalid query parameters, or field validation failure).
401 4xx Client Error 🔥 Interview Screener Unauthorized Authentication missing or invalid token ("Who are you?"). Missing JWT or session cookie.
403 4xx Client Error 🔥 Interview Screener Forbidden User is authenticated, but lacks permission/role ("I know who you are, but you cannot access this resource").
404 4xx Client Error Not Found Requested URL endpoint or database resource ID does not exist.
405 4xx Client Error Method Not Allowed HTTP method used is not supported by endpoint (e.g., sending POST to a read-only GET endpoint).
409 4xx Client Error 🔥 Interview Screener Conflict Resource state conflict (e.g. duplicate email registration or booking a movie seat already reserved).
429 4xx Client Error 🔥 Interview Screener Too Many Requests Client exceeded rate limits / API throttling rules. Protects servers against spam & DDoS attacks.
500 5xx Server Error Internal Server Error Generic server crash or uncaught exception in backend code (e.g. NullPointerException or DB crash).
502 5xx Server Error 🔥 Interview Screener Bad Gateway Reverse proxy (Nginx / API Gateway) received an invalid / corrupted response from backend application server.
503 5xx Server Error Service Unavailable Server temporarily overloaded or undergoing maintenance. Usually temporary.
504 5xx Server Error 🔥 Interview Screener Gateway Timeout Reverse proxy (Nginx / API Gateway) timed out waiting for downstream backend microservice to respond.

🎓 Top HTTP Status Code Screening Interview Questions & Answers

Q1: 401 Unauthorized vs 403 Forbidden? 401: Authentication error ("Who are you?"). Missing or invalid credentials.
403: Authorization error ("I know who you are, but you don't have role permission").
Q2: When to use 204 No Content vs 200 OK? 204: Action succeeded (e.g. DELETE /api/users/1) with intentionally no response body payload.
200: Action succeeded and returns a JSON payload.
Q3: How does 304 Not Modified save bandwidth? Client sends If-None-Match: "v1" header. If server data hasn't changed, server returns 304 without body payload, saving mobile data.
Q4: Difference between 502 Bad Gateway & 504 Gateway Timeout? 502: Proxy received a malformed/corrupted response from backend.
504: Proxy timed out waiting for backend microservice to answer.
Q5: What is 429 Too Many Requests used for? Used in API Rate Limiting & Throttling to prevent API abuse, scraping, or DDoS attacks. Response often includes Retry-After header.
Q6: Why return 409 Conflict during registration? Returned when a client request conflicts with current server state — e.g. trying to register with an email address that is already registered in DB.

📋 Headers: Metadata of Communication

Concept: Headers convey metadata (Content-Type, Authorization, Cache-Control). They affect behavior without touching body content.

⏱️ Synchronous vs Asynchronous Requests

Concept: Synchronous blocks UI; asynchronous doesn't. Use async for good UX.
Synchronous is like standing at an ATM waiting; asynchronous is ordering online and continuing work until it arrives.
