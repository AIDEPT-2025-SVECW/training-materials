2. Famous Deployment Strategies Deep-Dive

🔵🟢 Blue-Green Deployment

Zero Downtime

Maintains two identical physical/cloud environments: Blue (Current Active Production) and Green (Idle / New Version). Version 2 is deployed & tested fully in Green. Once verified, the Load Balancer router flips traffic instantly to Green!

✈️
Analogy: Building a brand new identical airport runway alongside the old one. Once completed, air traffic control flips one switch to land all planes on the new runway.
  • Pros: Instant rollback (<1 sec switch back to Blue), zero downtime, safe testing on real production environment.
  • Cons: High cost (requires 2x infrastructure during release), database schema migrations must be backward-compatible.
0 Sec
High ($$$)
< 1 Sec
Very Low

🐤 Canary Deployment

Blast Radius Control

Releases Version 2 to a small subset of users first (e.g. 5% or 10%) while 90% remain on v1. DevOps teams monitor error rates, CPU, and latency via Prometheus/Grafana. If metrics are healthy, traffic is gradually increased (10% ➔ 25% ➔ 50% ➔ 100%).

🐥
Analogy: Coal miners taking a canary bird into toxic gas mines. If the bird survived, it was safe for human miners to enter.
  • Pros: Minimal blast radius (only 5% of users affected if v2 has bugs), real production traffic testing, auto-rollback triggers.
  • Cons: Requires complex traffic routing (Istio / Nginx / AWS ALB), takes longer to complete 100% rollout.
0 Sec
Medium ($$)
Fast
Minimal

🔄 Rolling Deployment

Kubernetes Default

Gradually replaces old server instances with new server instances one by one or in batches (e.g. 25% at a time). The Load Balancer takes one server offline, upgrades it to v2, verifies health check, and brings it back online before moving to the next.

🏟️
Analogy: Upgrading stadium seats section by section while a live match is ongoing without stopping the game.
  • Pros: Zero downtime, no extra server costs (uses existing infrastructure pool), standard for Kubernetes RollingUpdate.
  • Cons: Rollback takes time (must undo instance by instance), temporary period where both v1 and v2 coexist simultaneously.
0 Sec
Low ($)
Medium
Moderate

🔴 Recreate (Big Bang)

Downtime Window

Completely shuts down all Version 1 servers ➔ System goes offline ➔ Deploys Version 2 ➔ Boots all servers back up. Simplest approach, but causes noticeable service downtime.

🛠️
Analogy: Closing a restaurant completely for 2 weeks to renovate the kitchen before reopening.
  • Pros: Easiest setup, no backward compatibility issues (no mixed v1/v2 state), zero extra infrastructure cost.
  • Cons: Planned downtime required, high risk if v2 fails during boot up.
Required
Low ($)
Slow
High

👻 Shadow / Dark Deployment

Silent Production Test

Version 2 is deployed alongside Version 1. The Load Balancer duplicates incoming live production traffic and sends an exact copy asynchronously to v2. v2's responses are discarded and never returned to real users. Used to test load, memory leaks & performance under true production traffic!

👨‍🍳
Analogy: A shadow chef in a back room cooking every customer order in parallel to test cooking speed, but throwing the extra food away.
  • Pros: Zero user impact, 100% realistic production load testing without risk.
  • Cons: Expensive, side-effects MUST be mocked/disabled (e.g. don't send duplicate emails or double-charge credit cards!).

High ($$$)
Instant

🧪 A/B Testing Deployment

Business Metric Split

Routes targeted subsets of users based on cookies, geolocation, user ID, or HTTP headers to Version A vs Version B to evaluate business metrics (e.g., checkout conversion rate).

📋
Analogy: Giving half your restaurant guests Menu A and half Menu B to test which menu design generates higher sales.
  • Pros: Data-driven product decisions, precise targeting, feature flag integration.
  • Cons: Requires analytics tracking infrastructure & complex routing rules.

3. DevOps Strategy Comparison Matrix

Quick reference summary table for architecture reviews and interview preparation:

Strategy Downtime Infrastructure Cost Rollback Speed Blast Radius Best Used For
🔴 Recreate Yes (Minutes/Hours) Low ($) Slow (Re-deploy v1) 100% of Users Development/Staging environments, non-critical batch apps.
🔄 Rolling Zero Downtime Low ($) Medium (Instance by instance) Partial Users Standard microservices, Kubernetes stateless applications.
🔵🟢 Blue-Green Zero Downtime High ($$$) < 1 Second Switch All or None Mission-critical banking, payment gateways, major release cutovers.
🐤 Canary Zero Downtime Medium ($$) Fast (Route back to v1) Confined (5% - 10%) High-traffic platforms (Netflix, Swiggy, Uber) testing new features.
👻 Shadow Zero Downtime High ($$$) Instant (Stop duplicate) 0 Users (Silent) Performance load testing, algorithm upgrades under real load.
🧪 A/B Testing Zero Downtime Medium ($$) Instant (Toggle Flag) Target Segment Product experimentation, UI redesigns, conversion optimization.
