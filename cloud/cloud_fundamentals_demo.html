Why Cloud Computing? Advantages & Architecture

Cloud computing delivers on-demand compute, storage, databases, and networking over the Internet with pay-as-you-go pricing—replacing physical data centers with elastic, software-defined infrastructure.

Context: Full Stack Engineering Course (Session 8: Cloud Infrastructure & Service Models).

The Shift from Traditional On-Premises Data Centers to Cloud

Before cloud computing, companies had to purchase physical servers, lease data center space, install cooling & backup generators, and hire system administrators. This model created huge financial and operational friction.

Traditional On-Premises

The Hardware Bottleneck

  • High CapEx: Huge upfront capital expenditure on physical servers, routers, and SAN storage.
  • Slow Procurement: Buying & racking a new server takes 4 to 12 weeks.
  • Wasted Capacity: Hardware must be over-provisioned for peak traffic, sitting idle 90% of the time.
  • Single Points of Failure: Local power outages or hardware faults take down the entire system.
Modern Cloud Computing

On-Demand Elasticity

  • OpEx Model: Zero upfront cost; convert capital expenses into variable monthly operational expenses.
  • Instant Provisioning: Spin up 100 virtual servers globally in seconds via API or CLI.
  • Auto-Scaling: Automatically add capacity during traffic surges and shrink back to save money.
  • Global High Availability: Multi-region replication and 99.99%+ SLA uptime guarantees.

The 6 Primary Pillars & Advantages of Cloud Computing

Cloud providers like AWS, Google Cloud (GCP), and Microsoft Azure solve key software deployment challenges through six core benefits:

1. Trade CapEx for OpEx
Pay only for compute resources you consume (Pay-As-You-Go). No massive upfront hardware investments or server depreciation schedules.
2. Massive Economies of Scale
Cloud providers aggregate traffic from millions of customers, allowing them to purchase hardware at lower prices and pass savings down to you.
3. Stop Guessing Capacity
Eliminate server crashes during flash sales. Auto-scaling handles traffic spikes automatically without overpaying for unused capacity.
4. Increased Speed & Agility
New IT resources are just a click away. Experiment, launch new features, and deploy code updates in minutes instead of months.
5. Zero Data Center Overhead
Focus on writing business code. The cloud vendor handles rack mounting, power, cooling, OS patches, hardware replacements, and cabling.
6. Go Global in Minutes
Deploy applications in multiple geographical regions worldwide with a few clicks, delivering lower latency and better UX to global users.

Cloud Service Delivery Models (IaaS, PaaS, SaaS)

Cloud offerings are categorized by how much control you maintain versus how much responsibility you offload to the vendor. This is known as the Shared Responsibility Model.

Infrastructure as a Service (IaaS)

Raw Compute & Networking

You get virtual machines, storage, and firewalls. You manage OS installation, security patches, and app runtime.

Examples: AWS EC2, Google Compute Engine, Azure VM

Platform as a Service (PaaS)

Developer Application Platform

Vendor manages OS, database servers, and runtime env (Java/Node). You only upload your application code!

Examples: Heroku, AWS Elastic Beanstalk, App Engine

The Shared Responsibility Matrix

Compare who manages what layer across On-Premises, IaaS, PaaS, and SaaS:

Infrastructure Layer On-Premises IaaS PaaS SaaS
Application Code & Data You Manage You Manage You Manage Cloud Provider
Runtime & Middleware You Manage You Manage Cloud Provider Cloud Provider
Operating System (OS) You Manage You Manage Cloud Provider Cloud Provider
Virtualization & Hypervisor You Manage Cloud Provider Cloud Provider Cloud Provider
Servers, Storage & Physical Net You Manage Cloud Provider Cloud Provider Cloud Provider
