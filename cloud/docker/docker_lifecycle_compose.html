⚡ Step 2 — Container Lifecycle States

Container Runtime State Machine

Understand the 4 key runtime states a container transitions through during its life.

1. Created

Container created via docker create, but process is not yet started.

2. Running

Process active & executing in RAM via docker run or docker start.

3. Paused

Container processes frozen in place via docker pause (Zero CPU usage).

4. Stopped / Exited

Process terminated via docker stop. Can be restarted or destroyed (`docker rm`).

🐙 Step 3 — Multi-Container Orchestration

Docker Compose Brief Overview

Why run 5 messy terminal commands when you can launch your ENTIRE full-stack app with 1 command?

💡 What Problem does Docker Compose Solve?
Running 1 single container with docker run is easy. But a real Full-Stack Food Ordering app requires 3 connected containers: React Frontend + Spring Boot Backend + PostgreSQL Database. Docker Compose lets you define all 3 containers in a single docker-compose.yml file and launch them together using docker compose up -d!

📄 docker-compose.yml File Structure

version: '3.8'
services:
  backend:
    build: ./backend
    ports: ["8080:8080"]
    environment:
      - DB_HOST=postgres

  postgres:
    image: postgres:15
    volumes: [db-data:/var/lib/postgresql/data]

volumes:
  db-data:
