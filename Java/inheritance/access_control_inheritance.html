🔑 Visibility Rules in Inheritance

📦 Quick Primer: What is a Package & Why Do We Need It?

(Brief Overview — Packages will be covered in full detail in a dedicated module later!)

A Package in Java is essentially a directory folder on your disk that groups related classes, interfaces, and sub-packages together (e.g., package com.bank.parent;).

  • Prevents Naming Collisions: Two classes can share the exact same name as long as they live in different packages (e.g. java.util.Date vs java.sql.Date).
  • Access Control Boundary: Access modifiers like default (package-private) and protected rely directly on package boundaries to restrict or allow visibility.
  • Analogy: Packages are like Indian City Districts (e.g., in.delhi vs in.hyderabad). Both cities can have a MG Road without any postal delivery confusion!

🏡 Real-World Indian Analogy: Ancestral Home Security

  • private: Personal Diary locked in Father's personal safe. Even though it is inside the house (memory), children cannot read it directly!
  • default (Package-Private): Living room Smart TV. Anyone living in the same apartment complex (same package) can use it. But relatives living in another city (different package) cannot!
  • protected: Ancestral Farmland & Secret Family Masala Recipe. Children can access it EVEN IF they move to another city (different package) via inheritance!
  • public: Sweet Shop counter on main road. Accessible to anyone anywhere.

Are Private members inherited?

YES in memory, NO in direct code! Private fields of a superclass are present inside the subclass object memory layout on heap, but the subclass code cannot access them directly by variable name. They must be accessed via inherited public or protected getter/setter methods.

The Power of protected

The protected modifier is specially designed for inheritance! It allows a subclass in a different package to access the parent's protected members via inheritance (using super or direct field name inside subclass code).
