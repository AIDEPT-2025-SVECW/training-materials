Method Overriding & Rules

Learn how subclasses redefine superclass methods to achieve Runtime Polymorphism, and master the strict rules governing signatures, covariant return types, and access visibility.

🔄 Method Overriding ⚡ Runtime Polymorphism 🏷️ @Override Annotation 🧬 Covariant Return Types

🔄 What is Method Overriding?

When a subclass defines a method with the exact same signature (name, parameter types, return type/covariant) as a method in its superclass, the subclass method overrides the parent's method.

🏦 Real-World Indian Analogy: Reserve Bank of India vs Commercial Banks

The RBI (Reserve Bank of India) defines a standard base method: double getHomeLoanInterestRate() which returns a benchmark rate of 6.5%. Commercial Indian banks override this method:

  • SBI_Bank overrides getHomeLoanInterestRate() to return 8.4%.
  • HDFC_Bank overrides getHomeLoanInterestRate() to return 8.65%.

Each commercial bank customized the behavior while maintaining the standard RBI signature!

The 5 Golden Rules of Overriding

  1. Method Signature: Name and parameter types must match 100%.
  2. Return Type: Must be identical OR a subtype (Covariant Return Type).
  3. Access Visibility: Cannot reduce visibility (e.g. protected -> public OK; public -> private FAILS).
  4. Exception Rule: Cannot throw new/broader checked exceptions.
  5. Non-Overridable Methods: private, static, and final methods CANNOT be overridden.

Why use @Override?

The @Override annotation tells the Java compiler to verify that you are actually overriding a superclass method. If you make a typo (e.g. getHomeLoanInterest() instead of getHomeLoanInterestRate()), compiler immediately catches it as an error!

🛑 Deep Dive: Why Static Methods CANNOT Be Overridden (Method Hiding)

1. Class-Level vs Instance-Level:
static methods belong to the Class itself (stored in Metaspace), NOT to individual object instances on Heap. Method Overriding requires a runtime object instance on Heap to perform Virtual Method Table (VTable) dynamic dispatch.

2. Static Binding (Compile-Time) vs Dynamic Binding (Runtime):
Method Overriding relies on Dynamic Binding (resolved at runtime based on the actual Heap object). In contrast, calls to static methods use Static Binding — the Java compiler binds static method calls at compile time based strictly on the Reference Type!

⚠️ Method Hiding (Not Overriding!):
If a subclass defines a static method with the exact same signature as a parent's static method, Java compiler does NOT override it. This is called Method Hiding.

Parent p = new Child();
p.staticMethod(); // ➔ ALWAYS calls Parent's static method because reference 'p' is Parent!

Feature Method Overloading Method Overriding
Polymorphism Type Compile-Time (Static Binding) Runtime (Dynamic Binding)
Class Location Within the SAME class or SUBCLASS Must be between SUPERCLASS & SUBCLASS
Method Signature Must have DIFFERENT parameters Must have EXACT SAME parameters
Return Type Can be same or different Must be same or Covariant

💻 Complete Java Code: Indian Bank Interest Rates

BankInterestDemo.java
// Parent Superclass class RBI_Bank { public double getHomeLoanInterestRate() { return 6.5; // RBI Benchmark Rate } } // Subclass 1 class SBI_Bank extends RBI_Bank { @Override public double getHomeLoanInterestRate() { return 8.40; // Overridden SBI Rate } } // Subclass 2 class HDFC_Bank extends RBI_Bank { @Override public double getHomeLoanInterestRate() { return 8.65; // Overridden HDFC Rate } } public class OverridingDemo { public static void main(String[] args) { RBI_Bank sbi = new SBI_Bank(); RBI_Bank hdfc = new HDFC_Bank(); System.out.println("SBI Rate: " + sbi.getHomeLoanInterestRate() + "%"); // 8.4% System.out.println("HDFC Rate: " + hdfc.getHomeLoanInterestRate() + "%"); // 8.65% } }
