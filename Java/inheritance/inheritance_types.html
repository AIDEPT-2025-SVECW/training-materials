📐 Classification of Inheritance Types

Inheritance types in computer science are fundamentally divided into two major categories: Single-Parent Categories and the Multiple Inheritance Bucket (having >1 parent).

1️⃣ Category A: Single-Parent Inheritance (1 Direct Parent)

Single Level Class Supported

A single child class extends a single parent class.

Example: Car extends Vehicle

Multilevel Class Supported

Sequential chain where each subclass extends 1 direct parent.

Example: NexonEV extends Car extends Vehicle

Hierarchical Class Supported

Multiple child classes each extend 1 common superclass.

Example: Bike extends Vehicle & Car extends Vehicle

🔄 Category B: The Multiple Inheritance Bucket (Multiple Direct Parents)

Key Insight: Multiple Inheritance with Classes, Hybrid Inheritance, and Multiple Interface Inheritance are ALL variants under the Multiple Inheritance Family because a child inherits from more than 1 direct parent.

Variant 1: Multiple (Classes) Class Unsupported

Child class extending multiple parent classes directly (class C extends A, B).

Forbidden in Java due to Diamond Ambiguity!

Variant 2: Hybrid Inheritance Class Unsupported

Combination of multiple inheritance with single/multilevel trees.

Forbidden for classes; supported via Interfaces!

Variant 3: Multiple (Interfaces) Interface Supported

A class implementing multiple interface contracts (implements A, B).

Fully Supported in Java! (Contract Inheritance)

💎 Why Java Disallows Multiple Inheritance for Classes

Suppose class Child could extend both Father and Mother classes, and both parent classes had a method with the exact same signature: void cookDinner().

🍛 Real-World Indian Analogy: Mother vs Father Cooking Conflict

If Father cooks Butter Chicken and Mother cooks Paneer Butter Masala under the exact same method signature cookDinner(), when the Child object calls child.cookDinner(), which recipe should JVM execute? There is 100% ambiguity!

To prevent runtime confusion, memory layout conflicts, and diamond complexity, Java creators completely prohibited class Child extends Father, Mother!

💡 Deep Dive: Then Why Does Java Allow Multiple Inheritance using Interfaces?

What is an Interface? (Brief Overview — we will explore Interfaces in extensive depth in a dedicated upcoming module!)
An Interface in Java is a pure contract that specifies WHAT a class must do, without defining HOW to do it. Unlike classes, interfaces do NOT contain instance variables (state) or constructors.

📌 Key Golden Rule: Classes inherit State + Behavior (causing Diamond Ambiguity). Interfaces inherit Contracts Only (safe & clean for Multiple Inheritance).
