1. Nested Classes Taxonomy

Static Nested Class

Declared with the static keyword inside an outer class. It is behaviorally like a top-level class nested for packaging convenience, and does NOT hold an implicit reference to an instance of the outer class.

class Outer {
  private static String company = "TechCorp";
  private int outerId = 101;

  public static class StaticNested {
    public void display() {
      System.out.println(company); // ✅ Allowed (static field access)
      // System.out.println(outerId); ❌ Error! Cannot access non-static outerId
    }
  }
}

// Instantiation Syntax (No Outer Object Needed!):
Outer.StaticNested nested = new Outer.StaticNested();

Member Inner Class (Non-Static)

Declared without static inside a class. Every instance of an Inner Class is bound to an instance of the Outer Class and can directly access all outer fields (including private instance fields) via Outer.this.

class Outer {
  private int secret = 42;

  public class Inner {
    public void showSecret() {
      System.out.println("Outer Secret: " + secret); // ✅ Direct access!
    }
  }
}

// Instantiation Syntax (REQUIRES Outer Instance!):
Outer outer = new Outer();
Outer.Inner inner = outer.new Inner();

Local Inner Class

Defined inside a method body or block. It is scope-restricted to that method and can access method parameters/local variables only if they are effectively final (not modified after assignment).

public void processData() {
  final int factor = 10; // Must be final or effectively final

  class LocalHelper {
    void compute(int val) {
      System.out.println(val * factor);
    }
  }

  LocalHelper helper = new LocalHelper();
  helper.compute(5);
}

Anonymous Inner Class

An inner class declared and instantiated in a single expression without a class name. Frequently used to implement interfaces or override base class methods on the fly.

Runnable r = new Runnable() {
  @Override
  public void run() {
    System.out.println("Running inside Anonymous Class!");
  }
};
new Thread(r).start();

3. Execution Order: Static vs Instance Blocks vs Constructor

When a class is instantiated in Java, execution strictly follows this hierarchy:
Static Initializer Blocks (Once on Class Load) → Instance Initializer Blocks → Constructor Body.

class Demo {
  static {
    System.out.println("1. Static Initializer Block (Runs ONCE)");
  }
  {
    System.out.println("2. Instance Initializer Block (Runs every object)");
  }
  public Demo() {
    System.out.println("3. Constructor Body (Runs every object)");
  }
}

4. Deep-Dive Accordion Explorer

1. Methods Revisited – Modifier Combination Matrix
▲

Not all Java method modifiers can be used together! Here is the authoritative validity rule matrix:

Combination Status Explanation & Behavior
public static final VALID Global static constant method or utility method that cannot be overridden or hidden.
private final VALID Allowed by compiler, but final is redundant because private methods cannot be overridden anyway.
abstract final ILLEGAL Contradiction! abstract demands overriding in subclasses, while final strictly forbids overriding.
static abstract ILLEGAL Contradiction! static methods belong to class and resolve at compile-time; abstract requires instance runtime polymorphism.
private abstract ILLEGAL Contradiction! private hides the method from subclasses, making it impossible for subclasses to implement the abstract contract.
2. Method Nesting Myth vs Reality
▼

The Myth: "Can you define a method directly inside another method in Java like in Python or JavaScript?"
The Reality: ❌ No! Direct method nesting is illegal in Java syntax.

public void outerMethod() {
  // Illegal Java Syntax:
  // public void innerMethod() {} ❌ Compile Error!
}

How Java Solves Method-Local Logic:

  • Local Inner Classes: Define a class inside the method body.
  • Lambda Expressions (Java 8+): Pass functional behaviors inline e.g. Consumer<String> print = msg -> System.out.println(msg);
3. Variable Arguments (varargs: type... name)
▼

Varargs allow a method to accept zero or multiple arguments of a specified type without creating an array explicitly at call site.

public static void printNumbers(int... numbers) {
  for (int num : numbers) {
    System.out.print(num + " ");
  }
}

// Call Site Examples:
printNumbers(); // 0 args
printNumbers(10, 20, 30); // 3 args

Golden Rules for varargs:

  1. There can be only ONE vararg parameter per method signature.
  2. The vararg parameter MUST be the LAST parameter in the list (e.g. void test(String msg, int... vals) ✅).
