🤝 Methods Declaration Taking Another Object as a Parameter

In Object-Oriented Programming, objects don't exist in isolation—they interact with one another! A method in Class A can accept an instance of Class B (or another instance of Class A) as a parameter.

Inter-Object Interaction

In the code on the right, transferFunds() is invoked on acc1 (the calling object this), and accepts targetAcc (another BankAccount object) as a parameter.

  • this.balance accesses the calling object's balance in Heap.
  • targetAcc.balance accesses the parameter object's balance in Heap.
  • Both objects mutate state simultaneously!
💡 Real-World Use Cases
Bank transfers (acc1.transfer(acc2, 500)), comparing two objects (emp1.equals(emp2)), or merging collections!
// BankAccount.java
public class BankAccount {
  String accountNumber;
  double balance;

  public BankAccount(String accNo, double bal) {
    this.accountNumber = accNo;
    this.balance = bal;
  }

  // Method taking ANOTHER BankAccount object parameter
  public void transferFunds(BankAccount targetAcc, double amount) {
    if (this.balance >= amount) {
      this.balance -= amount; // Mutates calling object
      targetAcc.balance += amount; // Mutates target object!
    }
  }
}

🔗 Object Reference Variables & Reference Aliasing

1. Reference Variables store Address Pointers

When you write BankAccount b1 = new BankAccount("A101", 1000);, variable b1 does NOT hold the object itself. It holds a memory address pointer (e.g. 0x4A10) referencing the object in Heap memory!

2. What is Reference Aliasing?

When you assign one reference variable to another (BankAccount b2 = b1;), the memory address pointer 0x4A10 is copied to b2. Now both `b1` and `b2` point to the EXACT SAME object in Heap memory!

⚠️ Pointer Aliasing Effect
Modifying state via b2.balance = 5000; instantly affects b1.balance because there is only ONE physical object in Heap memory being shared by two pointers!
// Reference Aliasing Example
BankAccount b1 = new BankAccount("A101", 1000.0);
// b1 holds address 0x4A10

BankAccount b2 = b1; // Copies address pointer 0x4A10 into b2!
// Both b1 and b2 point to 0x4A10

b2.balance = 5000.0; // Mutates object at 0x4A10

System.out.println(b1.balance); // Prints 5000.0!
System.out.println(b1 == b2); // true (Identical addresses!)
⚡ Deep Dive: Java is STRICTLY 100% Pass-by-Value!
📢 The Universal Golden Rule of Java
Java is STRICTLY 100% Pass-by-Value ONLY! There is NO Pass-by-Reference in Java!
A. Passing Primitives
Primitive Pass-by-Value

When passing a primitive (int, double, boolean), a copy of the primitive value (e.g. 10) is passed to the method parameter.

void modifyPrimitive(int x) {
  x = 99; // Modifies copy ONLY
}
int num = 10;
modifyPrimitive(num);
// num is STILL 10! Unchanged!
B. Passing Objects
Reference Pointer Pass-by-Value

When passing an object reference, a copy of the reference address pointer (e.g. `0x4A10`) is passed into the method parameter!

void modifyObject(BankAccount acc) {
  // acc is a COPY of reference pointer 0x4A10
  acc.balance = 9999; // Mutates Heap object!
}
BankAccount myAcc = new BankAccount(...);
modifyObject(myAcc);
// myAcc.balance IS UPDATED to 9999!

Why do people mistakenly call it "Pass-by-Reference"? Because passing a copy of an object's reference address allows the method to mutate the original object's fields in Heap memory! However, passing the pointer by value is NOT the same as pass-by-reference. See Tab 4 to see why!

🔀 Field Mutation vs Parameter Reference Reassignment

This is the classic Java interview test! Observe what happens when a method mutates fields vs when a method reassigns the parameter variable:

public class TestDemo {
  public static void main(String[] args) {
    BankAccount account = new BankAccount("ACC-101", 1000.0); // Address 0x4A10

    processAccount(account);
    System.out.println(account.accountNumber); // Prints "ACC-101" (NOT "NEW-999"!)
    System.out.println(account.balance); // Prints 5000.0 (Field mutation worked!)
  }

  public static void processAccount(BankAccount b) {
    // Case 1: Field Mutation (Modifies shared Heap object at 0x4A10)
    b.balance = 5000.0; // ✅ CALLER SEES THIS CHANGE!

    // Case 2: Parameter Reference Reassignment
    b = new BankAccount("NEW-999", 9999.0); // Reassigns ONLY local parameter b to 0x88F0!
    b.balance = 7777.0; // Modifies ONLY local temporary object!
  }
}

🎯 Object References & Pass-by-Value Self-Assessment Quizzes
1. Is Java Pass-by-Value or Pass-by-Reference?
A) Strictly 100% Pass-by-Value ONLY
B) Pass-by-Reference for Objects, Pass-by-Value for Primitives
C) Pass-by-Reference for all variables
🎉 Correct! Java is strictly 100% Pass-by-Value. When an object is passed, a copy of the reference address pointer is passed by value!
2. When you assign `b = new BankAccount()` inside a method parameter `b`, does it change the caller's reference variable?
A) Yes, caller's variable now points to the new object
B) NO, it reassigns ONLY the method's local copied reference variable
C) It causes a NullPointerException
🎉 Correct! Reassigning parameter `b` changes only the local copied reference pointer in the method stack frame. The caller's reference remains unchanged!
3. If you mutate a field `b.balance = 5000` inside a method parameter `b`, is it visible to the caller?
A) YES, because both caller and method references point to the SAME Heap object
B) No, changes to object fields are lost when method exits
C) Only if the method returns the object
🎉 Correct! Because `b` holds a copy of the memory address pointer to the shared Heap object, field mutations affect the physical Heap instance!
4. What does `b1 == b2` evaluate when `b1` and `b2` are object reference variables?
A) Compares field values of the two objects
B) Checks if `b1` and `b2` hold the exact same memory address pointer
C) Compares class names
🎉 Correct! The `==` operator on object references compares memory address pointers, checking if both variables point to the same Heap instance.
