Memory Management & Garbage Collection

Learn how Java automatically manages Heap memory, how objects become eligible for Garbage Collection, and why you never need to manually free memory in Java!

🧠

1. Memory Architecture Recap

In Java, memory is divided into two primary runtime areas: Stack Memory and Heap Memory.

📚 Stack Memory

Stores local primitive variables and object reference pointers. Stack memory is thread-safe, fast, and automatically cleaned up when method execution finishes.

🏔️ Heap Memory

Stores all dynamically created Java Objects (via new operator). Shared across all threads. Managed automatically by the Garbage Collector (GC).

♻️

2. What is Garbage Collection (GC)?

In languages like C or C++, developers must explicitly allocate (`malloc`) and deallocate (`free`) memory. Forgetting to free memory causes Memory Leaks.

In Java, the Garbage Collector is a background JVM daemon thread that automatically reclaims memory occupied by unreachable objects on the Heap.

How an Object Becomes Eligible for GC:

1. Nullifying Reference
Student s = new Student();
s = null; // Object is now unreachable!
2. Reassigning Reference
Student s1 = new Student("JP");
Student s2 = new Student("Rahul");
s1 = s2; // "JP" object is now unreachable!
3. Out of Scope
public void create() {
  Student temp = new Student();
} // temp reference dies when method returns

4. System.gc() — Myth vs Reality

Can you force Garbage Collection in Java?

You can call System.gc() or Runtime.getRuntime().gc() in your code.

System.gc(); // Requesting Garbage Collector to run
⚠️ Crucial Interview Point: Calling System.gc() is only a request or suggestion to the JVM! It is NOT a guarantee that the Garbage Collector will run immediately. The JVM decides when it is optimal to execute GC based on memory pressure.
