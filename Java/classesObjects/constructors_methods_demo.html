⚡ Deep Dive: The `new` Keyword & Object Creation Lifecycle

When you write BankAccount acc = new BankAccount("ACC101", 5000.0);, Java performs a 4-phase lifecycle behind the scenes in Stack and Heap memory:

Lifecycle Phase:
📦 Stack Memory (Reference Variable)
🏢 Heap Memory (Object Instance)
1. Reference Variable
Stack Memory

BankAccount acc creates a variable slot in Stack memory that holds an 8-byte reference address pointer (e.g. 0x4A10). It does NOT hold the actual object data!

2. Memory Allocator
`new` Keyword

The new operator requests JVM Heap memory space large enough to hold all instance variables of the class and returns its unique memory address pointer.

3. State Initialization
Constructor Call

Immediately after memory allocation, JVM invokes the class constructor to initialize the instance variables with provided arguments.

🏗️ Constructor Concepts & Constructor Overloading

What is a Constructor?

A Constructor is a special block of code that is automatically called when an object is instantiated using the new keyword.

  • Must have the EXACT same name as the class.
  • Must NOT have any return type (not even void).
  • If you define no constructors, Java provides an implicit Default No-Arg Constructor.
  • If you define any constructor, the compiler no longer provides the default no-arg constructor!
💡 Constructor Overloading Principle
Defining multiple constructors in the same class with different parameter lists (different number, types, or order of parameters).
// BankAccount.java — Overloaded Constructors
public class BankAccount {
  String accountNumber;
  double balance;
  String ownerName;
  boolean isActive;

  // 1. No-Arg Constructor
  public BankAccount() {
    this.accountNumber = "UNASSIGNED";
    this.balance = 0.0;
    this.ownerName = "Guest";
    this.isActive = false;
  }

  // 2. Two-Parameter Constructor
  public BankAccount(String accNo, double bal) {
    this.accountNumber = accNo;
    this.balance = bal;
    this.ownerName = "Customer";
    this.isActive = true;
  }

  // 3. Four-Parameter Constructor
  public BankAccount(String accNo, double bal, String owner, boolean active) {
    this.accountNumber = accNo;
    this.balance = bal;
    this.ownerName = owner;
    this.isActive = active;
  }
}
🔗 `this` Keyword & `this(...)` Constructor Chaining

1. `this` Keyword for Field Shadowing

When constructor or method parameter names match instance field names, the parameter shadows the field. Use this.fieldName to explicitly refer to the current object's field.

2. Constructor Chaining with `this(...)`

Constructor Chaining allows one constructor to call another overloaded constructor in the same class using this(...).

⚠️ CRITICAL JAVA RULE: The 1st Statement Requirement
The call to this(...) MUST strictly be the VERY FIRST STATEMENT inside the constructor body! Placed anywhere else, Java will throw a compile error: call to this must be first statement in constructor.
// Elegant Constructor Chaining via this(...)
public class BankAccount {
  String accountNumber;
  double balance;
  String ownerName;
  boolean isActive;

  // Main Master Constructor
  public BankAccount(String accountNumber, double balance, String ownerName, boolean isActive) {
    this.accountNumber = accountNumber; // Shadow resolution
    this.balance = balance;
    this.ownerName = ownerName;
    this.isActive = isActive;
  }

  // Chained Constructor 1 (Delegates to Master)
  public BankAccount(String accountNumber, double balance) {
    this(accountNumber, balance, "Standard Client", true); // MUST BE LINE 1!
  }

  // Chained Constructor 2 (Delegates to 2-Arg)
  public BankAccount() {
    this("ACC-DEFAULT", 1000.0); // Delegates up chain!
  }
}

⚙️ Methods Definition & Method Overloading with Primitive Parameters

1. Anatomy of Method Definition

Methods define the behavior of objects. They accept parameters (primitive data types like int, double, boolean) and return results.

2. Method Overloading (Compile-Time Polymorphism)

Two or more methods in the same class can have the SAME name as long as their parameter lists are different (different number or types of parameters).

📌 Primitive Parameter Widening Rule
If you pass an int argument (e.g. 500) to a method expecting a double parameter (double amount), Java automatically performs implicit primitive widening conversion from int to double (500.0).
// Method Overloading with Primitive Parameters
public class BankAccount {
  double balance;

  // Method 1: Deposit single primitive double
  public void deposit(double amount) {
    this.balance += amount;
  }

  // Method 2: Deposit with transaction fee check
  public void deposit(double amount, boolean applyFee) {
    double fee = applyFee ? 2.50 : 0.0;
    this.balance += (amount - fee);
  }

  // Method 3: Calculate interest with primitive int months
  public double calculateInterest(int months) {
    return this.balance * 0.05 * (months / 12.0);
  }

  // Method 4: Overloaded interest with custom double rate & int months
  public double calculateInterest(int months, double customRate) {
    return this.balance * (customRate / 100.0) * (months / 12.0);
  }
}

🎯 Constructors & Methods Self-Assessment Quizzes
1. What is the return type of a Java Constructor?
A) void
B) Object reference type
C) Constructors have NO return type
🎉 Correct! Constructors must NOT have any return type specified (not even void).
2. Where MUST a `this(...)` constructor call be located inside a constructor body?
A) Strictly the VERY FIRST statement
B) The last statement before return
C) Anywhere inside the constructor body
🎉 Correct! Java strictly requires this(...) constructor chaining calls to be on the first line of the constructor.
3. What is Method Overloading in Java?
A) Multiple methods in the same class with the SAME name but DIFFERENT parameter lists
B) Redefining a method in a subclass with exact same signature
C) Creating multiple objects from the same class
🎉 Correct! Method overloading allows multiple methods to share a name as long as their parameter counts or types differ.
4. If you define a 3-parameter constructor in your class, what happens to the default no-arg constructor?
A) Java still provides it automatically
B) The compiler NO LONGER provides it automatically
C) It causes a compilation error
🎉 Correct! Once you explicitly write ANY constructor, Java stops generating the default implicit no-arg constructor.
