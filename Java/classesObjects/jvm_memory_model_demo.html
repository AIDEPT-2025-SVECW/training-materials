📦 Stack Memory
Thread-Private

Holds method call frames, local primitive variables, and object reference address pointers (e.g. 0x4A10). Operates LIFO (Last-In-First-Out). Fast execution & automatic deallocation.

🏢 Heap Memory
Shared (All Threads)

Holds actual physical Object instances and instance variables. Divided into Young Generation (Eden, Survivor) & Old Generation. Automatically managed by Garbage Collection.

📁 Metaspace
Native OS Memory

Stores class definitions, method bytecode, static variables, and runtime constant pool. Allocated out of off-heap native OS memory (Replaced PermGen in Java 8+).

🧠 JVM Memory Regions Breakdown & Comparison

Understanding how JVM allocates memory across Stack, Heap, and Metaspace is essential for writing high-performance Java applications and troubleshooting memory leaks.

💥 1. `java.lang.StackOverflowError`
Occurs when method calls exceed the thread's Stack size (most commonly caused by unbounded recursive method calls without a base condition).
💥 2. `java.lang.OutOfMemoryError: Java heap space`
Occurs when the JVM Heap is completely full and the Garbage Collector cannot free up memory to instantiate a new object (caused by memory leaks or small max heap size).

🛠️ JVM Startup Memory Settings & Flag Reference

When starting a Java application in production, you configure JVM memory limits using command-line startup flags:

1. Initial Heap Size
-Xms

Sets the initial memory size allocated to the Heap upon startup (e.g. -Xms512m or -Xms2g). Prevents frequent heap growth overhead during initial load.

2. Maximum Heap Size
-Xmx

Sets the upper limit of Heap memory the JVM is allowed to consume (e.g. -Xmx2g or -Xmx8g). If application exceeds this, OutOfMemoryError is thrown.

3. Thread Stack Size
-Xss

Sets memory size allocated to each thread's Stack (e.g. -Xss512k or -Xss1m). Lowering this allows creating more concurrent threads.

4. Metaspace Limits
-XX:MaxMetaspaceSize

Configures initial and maximum memory limits for native class metadata (e.g. -XX:MetaspaceSize=128m -XX:MaxMetaspaceSize=512m).

5. OOM Heap Dump
-XX:+HeapDumpOnOutOfMemoryError

Instructs JVM to automatically generate a .hprof Heap Dump snapshot when OutOfMemoryError occurs for post-mortem memory leak debugging.

💡 Production Best Practice: Setting -Xms equal to -Xmx
In production server environments (e.g. Docker, Kubernetes, AWS), always set -Xms equal to -Xmx (e.g. -Xms4g -Xmx4g). This pre-allocates the full heap on startup, avoiding costly Garbage Collector heap expansion pauses while running under heavy traffic!

🎯 JVM Memory Model Self-Assessment Quizzes
1. Where are physical Object instances stored in JVM memory?
A) Heap Memory
B) Stack Memory
C) Metaspace
🎉 Correct! All object instances reside in Heap Memory, while reference variables holding memory addresses reside in Stack Memory.
2. Which JVM startup flag controls the Maximum Heap Memory size?
A) -Xss
B) -Xms
C) -Xmx
🎉 Correct! -Xmx specifies Maximum Heap Memory (e.g. -Xmx4g), while -Xms sets Initial Heap Memory.
3. What error occurs if recursive method calls exceed the thread stack limit?
A) java.lang.StackOverflowError
B) java.lang.OutOfMemoryError
C) java.lang.NullPointerException
🎉 Correct! Excessive nested stack frames trigger a StackOverflowError on the thread stack.
4. Where does JVM store class definitions, bytecode, and metadata in Java 8+?
A) PermGen
B) Metaspace (Native OS Memory)
C) Young Generation
🎉 Correct! Java 8 replaced PermGen with Metaspace, which allocates class metadata in native OS memory.
