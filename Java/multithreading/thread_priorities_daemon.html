Thread Priorities & Daemon Threads in Java

Master how the JVM schedules CPU time slices using integer priority levels, and discover how background daemon threads provide non-blocking housekeeping services like Garbage Collection without preventing JVM shutdown.

1. Thread Priorities in Java (Scale 1 to 10)

Priority System

Every thread in Java is assigned an integer priority level from 1 to 10. When multiple threads are in the RUNNABLE state waiting for CPU time, the thread scheduler generally gives preference to threads with higher priority numbers.

MIN_PRIORITY = 1
Lowest preference
➔
NORM_PRIORITY = 5
Default (Normal)
➔
MAX_PRIORITY = 10
Highest preference

Key Methods:

  • t.setPriority(int newPriority): Changes priority (1 to 10). Passing < 1 or > 10 throws an IllegalArgumentException!
  • int p = t.getPriority(): Returns current thread priority integer.

🌱 Priority Inheritance Rule:

When a new thread is created, it inherits the priority of the thread that created it. Since the JVM starts the main thread with priority 5 (NORM_PRIORITY), all child threads created inside main default to priority 5 unless explicitly modified.

PriorityExample.java
public class PriorityExample {
    public static void main(String[] args) {
        Thread t1 = new Thread(() -> {
            System.out.println("t1 running with priority: " + Thread.currentThread().getPriority());
        });

        Thread t2 = new Thread(() -> {
            System.out.println("t2 running with priority: " + Thread.currentThread().getPriority());
        });

        t1.setPriority(Thread.MIN_PRIORITY); // 1
        t2.setPriority(Thread.MAX_PRIORITY); // 10

        t1.start();
        t2.start();
    }
}
t2 running with priority: 10 t1 running with priority: 1

2. The Reality: Priorities are Platform-Dependent Hints

Critical Architecture Rule

In Java theory, higher-priority threads are executed before lower-priority threads. However, in reality, Java thread priorities are merely suggestions (hints) to the underlying Operating System.

⚠️
The Golden Rule for Multi-Threading:
"Never rely on thread priorities for program correctness, thread ordering, or synchronization!"

🪟 Windows OS

Windows has 7 distinct priority levels. The JVM must compress Java's 10 priority numbers down to fit into these 7 levels. Multiple Java priority numbers map to the same OS level.

🐧 Linux OS

Linux uses the Completely Fair Scheduler (CFS) with nice values. Non-root users cannot arbitrarily increase thread priority to avoid starvation. Java priorities are often treated equally.

🛡️ Starvation Prevention

Modern OS schedulers dynamically boost lower-priority threads that have been waiting too long (aging) to prevent thread starvation.

3. User Threads vs. Daemon Threads: The JVM Lifecycle Decider

Core Concept

Java categorizes all threads into two distinct types:

👤 User Threads (Non-Daemon)

• High-priority foreground workers: They execute the core business tasks of your application (e.g., main thread, file downloaders, request handlers).
• JVM Lifeline: The JVM will NOT exit as long as at least ONE non-daemon user thread is still alive and running!

👻 Daemon Threads (Background Service)

• Low-priority background service providers: They provide support services to user threads (e.g., Garbage Collector, Finalizer, auto-save helpers).
• Instant Death: When all user threads terminate, the JVM shuts down immediately. Any remaining daemon threads are terminated abruptly!

Configuring a Daemon Thread:

To make a thread a daemon, call thread.setDaemon(true).

🚫
The Golden Rule for setDaemon():
You MUST call t.setDaemon(true) BEFORE calling t.start()!
If you call t.setDaemon(true) on an already-running thread, the JVM throws an IllegalThreadStateException at runtime!
DaemonExample.java
public class DaemonExample {
    public static void main(String[] args) {
        Thread bgDaemon = new Thread(() -> {
            while (true) { // Infinite loop
                System.out.println("  [Daemon] Running background housekeeping...");
                try { Thread.sleep(500); } catch (InterruptedException ignored) {}
            }
        });

        // CRITICAL: Must be called BEFORE start()
        bgDaemon.setDaemon(true);
        bgDaemon.start();

        System.out.println("Main thread is finishing now!");
        // When main thread ends, JVM terminates immediately.
        // bgDaemon will NOT keep the JVM alive!
    }
}
Main thread is finishing now! [Daemon] Running background housekeeping... >> JVM terminates immediately! The infinite loop daemon is stopped.

6. Complete Verified Java Demo: ThreadPrioritiesDaemonDemo.java

Verified Java 17 Demo

The following self-contained Java program demonstrates priority constants, setting priorities, and user vs daemon shutdown behavior using simple console output:

ThreadPrioritiesDaemonDemo.java
/**
 * Thread Priorities and Daemon Threads Demonstration
 * 
 * Demonstrates:
 * 1. Thread priority constants (MIN_PRIORITY=1, NORM_PRIORITY=5, MAX_PRIORITY=10)
 * 2. Priority inheritance from the parent (main) thread
 * 3. Changing priorities via setPriority() and inspecting with getPriority()
 * 4. User thread vs Daemon thread behavior with setDaemon() and isDaemon()
 * 5. JVM shutdown behavior when only daemon threads remain
 */
public class ThreadPrioritiesDaemonDemo {

    public static void main(String[] args) throws InterruptedException {
        System.out.println("==========================================================");
        System.out.println("    THREAD PRIORITIES & DAEMON THREADS DEMONSTRATION      ");
        System.out.println("==========================================================");

        // ---------------------------------------------------------------------
        // 1. Thread Priority Constants & Inspection
        // ---------------------------------------------------------------------
        System.out.println("\n--- 1. Thread Priority Constants ---");
        System.out.println("  Thread.MIN_PRIORITY  : " + Thread.MIN_PRIORITY);  // 1
        System.out.println("  Thread.NORM_PRIORITY : " + Thread.NORM_PRIORITY); // 5
        System.out.println("  Thread.MAX_PRIORITY  : " + Thread.MAX_PRIORITY);  // 10

        Thread current = Thread.currentThread();
        System.out.println("\n  Main Thread Priority: " + current.getPriority()); // 5
        System.out.println("  Main Thread isDaemon: " + current.isDaemon());     // false (user thread)

        // ---------------------------------------------------------------------
        // 2. Setting Custom Thread Priorities
        // ---------------------------------------------------------------------
        System.out.println("\n--- 2. Setting Custom Thread Priorities ---");
        Thread lowPriorityThread = new Thread(() -> {
            System.out.println("  [LowThread] Running with Priority: " + Thread.currentThread().getPriority());
        }, "LowThread");
        lowPriorityThread.setPriority(Thread.MIN_PRIORITY); // 1

        Thread highPriorityThread = new Thread(() -> {
            System.out.println("  [HighThread] Running with Priority: " + Thread.currentThread().getPriority());
        }, "HighThread");
        highPriorityThread.setPriority(Thread.MAX_PRIORITY); // 10

        lowPriorityThread.start();
        highPriorityThread.start();
        lowPriorityThread.join();
        highPriorityThread.join();

        // ---------------------------------------------------------------------
        // 3. User Thread vs Daemon Thread
        // ---------------------------------------------------------------------
        System.out.println("\n--- 3. User Thread vs Daemon Thread ---");
        Thread userThread = new Thread(() -> {
            System.out.println("  [UserThread] Started. isDaemon: " + Thread.currentThread().isDaemon());
            System.out.println("  [UserThread] JVM will WAIT for me to finish before exiting!");
        }, "UserThread");

        Thread daemonThread = new Thread(() -> {
            System.out.println("  [DaemonThread] Started. isDaemon: " + Thread.currentThread().isDaemon());
            System.out.println("  [DaemonThread] I provide background service (like Garbage Collection).");
            try {
                // Sleep for 3 seconds; but JVM exits when UserThread & main finish!
                Thread.sleep(3000);
                System.out.println("  [DaemonThread] This will NOT print if JVM exits early!");
            } catch (InterruptedException e) {
                System.out.println("  [DaemonThread] Interrupted.");
            }
        }, "DaemonServiceThread");

        // Set daemonThread to true BEFORE calling start()
        daemonThread.setDaemon(true);

        userThread.start();
        daemonThread.start();

        userThread.join();
        // Give daemon thread a brief moment to print initial output
        Thread.sleep(200);

        System.out.println("\n--- 4. JVM Automatic Shutdown ---");
        System.out.println("  [Main Thread] Main thread and UserThread have both finished.");
        System.out.println("  [Main Thread] Only DaemonServiceThread is running.");
        System.out.println("  [Main Thread] Result: JVM terminates immediately without waiting for daemon!");
        System.out.println("==========================================================");
    }
}

7. Common Pitfalls & Mistakes to Avoid

Crucial Rules

❌ Pitfall 1: Calling setDaemon() After start()

Once a thread has started, its daemon status cannot be altered. Calling t.setDaemon(true) on an active thread throws IllegalThreadStateException.

❌ Pitfall 2: Relying on Priority for Business Logic

Never assume a thread with priority 10 will always finish before a thread with priority 1. Priorities are non-binding scheduling hints that OS kernels can override.

❌ Pitfall 3: Critical I/O in Daemon Threads

Because the JVM can terminate daemon threads at any instant without running their finally blocks, never put database writes or file output operations inside daemon threads!

❌ Pitfall 4: Invalid Priority Integers

Passing any value less than 1 or greater than 10 (e.g. t.setPriority(0) or t.setPriority(11)) throws an immediate IllegalArgumentException.

8. Frequently Asked Questions & Interview Concepts

Interview Preparation

Click any question to reveal the comprehensive interview-grade answer:

Q1. What is the default priority of a thread in Java? ▼
Answer: The default priority of any thread is inherited from the thread that created it. The JVM initializes the main thread with priority 5 (Thread.NORM_PRIORITY). Consequently, all threads created directly inside main default to priority 5 unless explicitly changed using setPriority().
Q2. What happens if you call setDaemon(true) on a thread after calling start()? ▼
Answer: The JVM throws an IllegalThreadStateException at runtime. Daemon status must be set strictly while the thread is in the NEW state (before the OS thread has been allocated and ignited).
Q3. Will a daemon thread's finally block always execute? ▼
Answer: No! This is a common interview trap. When the last user thread finishes execution, the JVM halts immediately. The JVM does not wait for daemon threads to finish their current instruction, nor does it guarantee that active daemon finally blocks will run. For this reason, resource cleanup or critical file updates should never rely on daemon threads.
Q4. Why is thread priority platform-dependent in Java? ▼
Answer: Java relies on native Operating System kernel threads. Different operating systems have fundamentally different scheduling algorithms and priority ranges (e.g., Windows uses 7 levels, Linux CFS uses nice values from -20 to +19). Because the JVM cannot force an OS kernel to conform to Java's 1-to-10 model, Java priorities serve purely as non-binding hints.
Q5. Is the Java Garbage Collector a user thread or a daemon thread? ▼
Answer: The Garbage Collector (GC) is the classic textbook example of a daemon thread. It runs silently in the background managing heap memory. If it were a user thread, the application would never terminate because the GC would keep the JVM alive forever!

📌 Core Summary & Key Takeaways

  • Priority Range: 1 (MIN_PRIORITY) to 10 (MAX_PRIORITY); default is 5 (NORM_PRIORITY). Inherited from creator thread.
  • Platform Dependent: Priorities are suggestions to the OS scheduler; never use them for thread synchronization or execution guarantees.
  • User Threads: Foreground workers that keep the JVM alive until they complete.
  • Daemon Threads: Background service providers; JVM exits immediately when all user threads finish, regardless of running daemons.
  • setDaemon() timing: Must be called before start() to avoid IllegalThreadStateException.
