Creating Threads in Java: Thread vs. Runnable vs. Callable

Master the three foundational ways to define and launch concurrent tasks in Java. Understand why implementing Runnable is preferred over extending Thread, and how Java 5's Callable empowers you to return values and throw checked exceptions.

1. The Three Ways to Create Threads in Java

Architecture

In Java, a thread requires two components: a task to execute (the instructions) and an execution worker (an OS thread allocated by the JVM). Java provides three core mechanisms to define and run thread tasks:

1️⃣ Extending Thread Inheritance

Subclass java.lang.Thread and override its run() method.

• Method: public void run()
• Return: void (no result)
• Checked Exceptions: No
2️⃣ Implementing Runnable Preferred

Implement java.lang.Runnable and pass the instance to new Thread(runnable).

• Method: public void run()
• Return: void (no result)
• Supports Lambdas: Yes
3️⃣ Implementing Callable Java 5+

Implement Callable<V>, wrap with FutureTask<V>, and retrieve result via get().

• Method: V call() throws Exception
• Return: Generic Value V
• Checked Exceptions: Yes

2. Mechanism 1: Extending the Thread Class

Basic Mechanism

The simplest and most direct approach is to create a subclass of Java's built-in java.lang.Thread class and override its run() method.

The 3-Step Procedure:

1 Define a Class: Create a class that extends Thread.
2 Override run(): Put your code inside public void run(). This code executes on the new thread.
3 Instantiate and Call start(): Create an object with new MyThread() and invoke .start().
SimpleThreadExample.java
// Step 1: Subclass Thread
class MyThread extends Thread {

    public MyThread(String name) {
        super(name); // Optional: assign a friendly name to the thread
    }

    // Step 2: Override run()
    @Override
    public void run() {
        System.out.println("Thread is running! Name: " + getName());
    }
}

public class SimpleThreadExample {
    public static void main(String[] args) {
        // Step 3: Instantiate and start
        MyThread t1 = new MyThread("Thread-A");
        t1.start(); // Spawns a new OS thread and invokes run()
    }
}
Thread is running! Name: Thread-A

✓ Advantages:

  • Direct and very easy for beginners to understand.
  • Direct access to built-in Thread methods like getName(), getPriority(), interrupt() without needing Thread.currentThread().

✗ Critical Disadvantages:

  • Single Inheritance Limitation: Java does not allow multiple class inheritance. If your class extends Thread, it cannot extend any other class (such as Person, Vehicle, or JPanel)!
  • Tight Coupling: The job/task is permanently coupled to the thread execution mechanism.
⚡

3. Mechanism 2: Implementing the Runnable Interface (Best Practice)

Industry Standard

The recommended and most popular way to create threads in Java is by implementing the java.lang.Runnable interface. It represents a functional interface containing a single abstract method: public void run();.

The 3-Step Procedure:

1 Implement Runnable: Create a class with implements Runnable.
2 Implement run(): Put your simple task code inside public void run().
3 Pass to Thread and Call start(): Pass your runnable instance to new Thread(runnableTask), then call .start().
SimpleRunnableExample.java
// Step 1: Implement Runnable
class MyTask implements Runnable {

    // Step 2: Implement run()
    @Override
    public void run() {
        // Note: Must use Thread.currentThread() because MyTask is not a Thread object
        System.out.println("Task is running! Thread Name: " + Thread.currentThread().getName());
    }
}

public class SimpleRunnableExample {
    public static void main(String[] args) {
        // Step 3: Create task instance and pass into Thread worker
        MyTask task = new MyTask();
        Thread t1 = new Thread(task, "WorkerThread-1");
        t1.start(); // Starts thread and runs MyTask.run()
    }
}
Task is running! Thread Name: WorkerThread-1

Modern Java 8+ Lambda Shortcut:

Because Runnable has only one abstract method, you can write concise inline threads without creating a separate class:

LambdaThreadExample.java
public class LambdaThreadExample {
    public static void main(String[] args) {
        // Ultra-clean one-liner using Lambda Expression:
        Thread t = new Thread(() -> {
            System.out.println("Lambda thread running: " + Thread.currentThread().getName());
        }, "QuickLambdaThread");

        t.start();
    }
}
💡
Why is Runnable the Industry Standard?
1. OOP Flexibility: Your class remains free to extend any other class (e.g. class StudentTask extends Student implements Runnable).
2. Separation of Concerns: Separates what work to do (Runnable) from how to run it (Thread worker / Thread Pool).
3. Executor & Thread Pool Ready: You can pass Runnable tasks straight into modern thread pools (ExecutorService).

4. Mechanism 3: Implementing Callable & FutureTask (Java 5+)

Return Value & Exceptions

Both Thread and Runnable suffer from two major architectural limitations:

⚠️
The Two Limitations of Runnable.run():
1. Cannot Return a Result: public void run() has a void return type. If a thread calculates a value, it cannot directly return it to the caller thread.
2. Cannot Throw Checked Exceptions: run() cannot declare throws IOException or throws SQLException; all checked exceptions must be caught inside.

To solve this, Java 5 introduced java.util.concurrent.Callable<V>:

public interface Callable<V> { V call() throws Exception; // Returns generic type V, and can throw checked exceptions! }

How to Execute a Callable: The FutureTask Bridge

The Thread constructor only accepts a Runnable. To run a Callable with a standard Thread, Java provides FutureTask<V>, which implements both Runnable and Future!

SimpleCallableExample.java
import java.util.concurrent.Callable;
import java.util.concurrent.FutureTask;

// Step 1: Implement Callable with desired return type (e.g., String)
class MyCallable implements Callable<String> {

    // Step 2: Implement call()
    @Override
    public String call() throws Exception {
        System.out.println("Callable is running on: " + Thread.currentThread().getName());
        return "SUCCESS_DATA_100"; // Return result to caller!
    }
}

public class SimpleCallableExample {
    public static void main(String[] args) throws Exception {
        // Step 3: Wrap Callable inside FutureTask
        Callable<String> task = new MyCallable();
        FutureTask<String> futureTask = new FutureTask<>(task);

        // Step 4: Pass FutureTask to Thread worker and start
        Thread t = new Thread(futureTask, "CallableWorker-1");
        t.start();

        // Step 5: Retrieve returned value (blocks until the thread finishes)
        String result = futureTask.get();
        System.out.println("Main thread received result: " + result);
    }
}
Callable is running on: CallableWorker-1
Main thread received result: SUCCESS_DATA_100

7. Complete Verified Java Demo: CreatingThreadsDemo.java

Verified Java 17 Demo

The following self-contained program demonstrates all three mechanisms using simple, readable print statements:

CreatingThreadsDemo.java
import java.util.concurrent.Callable;
import java.util.concurrent.ExecutionException;
import java.util.concurrent.FutureTask;

/**
 * Creating Threads in Java Demonstration
 * 
 * Demonstrates the 3 mechanisms to create and run threads in Java:
 * 1. Extending java.lang.Thread
 * 2. Implementing java.lang.Runnable (Class and Lambda)
 * 3. Implementing java.util.concurrent.Callable with FutureTask
 */
public class CreatingThreadsDemo {

    // -------------------------------------------------------------------------
    // Approach 1: Extending the Thread class
    // -------------------------------------------------------------------------
    static class MyThread extends Thread {
        public MyThread(String name) {
            super(name); // Set custom thread name
        }

        @Override
        public void run() {
            System.out.println("  [Thread Class] Hello from MyThread! Thread Name: " + getName());
        }
    }

    // -------------------------------------------------------------------------
    // Approach 2: Implementing the Runnable interface
    // -------------------------------------------------------------------------
    static class MyRunnable implements Runnable {
        @Override
        public void run() {
            System.out.println("  [Runnable] Hello from MyRunnable! Thread Name: " + Thread.currentThread().getName());
        }
    }

    // -------------------------------------------------------------------------
    // Approach 3: Implementing the Callable interface
    // -------------------------------------------------------------------------
    static class MyCallable implements Callable<String> {
        @Override
        public String call() throws Exception {
            System.out.println("  [Callable] Computing on thread: " + Thread.currentThread().getName());
            return "SUCCESS_DATA_100"; // Can return a value!
        }
    }

    public static void main(String[] args) throws InterruptedException, ExecutionException {
        System.out.println("==========================================================");
        System.out.println("     CREATING THREADS IN JAVA: THREE CORE MECHANISMS      ");
        System.out.println("==========================================================");

        // --- 1. Extending Thread Class ---
        System.out.println("\n--- 1. Extending Thread Class ---");
        MyThread t1 = new MyThread("WorkerThread-1");
        t1.start();
        t1.join(); // Wait so console output displays in order

        // --- 2. Implementing Runnable Interface ---
        System.out.println("\n--- 2. Implementing Runnable Interface ---");
        MyRunnable myTask = new MyRunnable();
        Thread t2 = new Thread(myTask, "WorkerRunnable-2");
        t2.start();
        t2.join();

        // --- 2b. Runnable using Modern Lambda (Java 8+) ---
        System.out.println("\n--- 2b. Runnable using Modern Lambda (Java 8+) ---");
        Thread t3 = new Thread(() -> {
            System.out.println("  [Lambda] Quick inline task running on: " + Thread.currentThread().getName());
        }, "LambdaThread-3");
        t3.start();
        t3.join();

        // --- 3. Implementing Callable & FutureTask ---
        System.out.println("\n--- 3. Implementing Callable & FutureTask ---");
        Callable<String> callableTask = new MyCallable();
        FutureTask<String> futureTask = new FutureTask<>(callableTask);
        Thread t4 = new Thread(futureTask, "CallableThread-4");
        t4.start();

        // futureTask.get() blocks until the thread finishes and returns the result
        String result = futureTask.get();
        System.out.println("  [Main Thread] Received returned result from Callable: " + result);

        System.out.println("\n==========================================================");
        System.out.println("All thread creation demonstrations executed successfully!");
        System.out.println("==========================================================");
    }
}

8. Common Beginner Pitfalls & Mistakes to Avoid

Crucial Rules

❌ Mistake 1: Calling run() instead of start()

If you call t.run() directly, no new thread is spawned! The code inside run() simply executes synchronously on the current main thread like an ordinary method call. Always call t.start() to request a separate OS thread!

❌ Mistake 2: Starting a Thread Twice

Once a thread completes or starts running, calling t.start() a second time throws an immediate IllegalThreadStateException. Threads in Java have a one-time lifecycle; create a new instance if you need to run the task again.

❌ Mistake 3: Forgetting to Pass Runnable to Thread

Writing Thread t = new Thread(); t.start(); does nothing! Because no Runnable was passed, the default Thread.run() method is empty and immediately terminates. Always pass the task: new Thread(myRunnable).start().

❌ Mistake 4: Calling future.get() Prematurely

The futureTask.get() method is a blocking call. If called right after starting the thread, the calling thread will pause and wait until the computation completes, effectively making the execution sequential unless managed properly.

9. Frequently Asked Questions & Interview Concepts

Interview Preparation

Click any question to reveal the comprehensive interview-grade answer:

Q1. Why is implementing Runnable considered superior to extending Thread? ▼
Answer: There are three primary design reasons:
1. Multiple Inheritance: Java does not support multiple class inheritance. If your class extends Thread, it cannot extend any other class. Implementing Runnable leaves your class free to inherit from your business model or GUI hierarchy.
2. Separation of Concerns: Runnable defines what code to execute, whereas Thread defines how to execute it. Decoupling them follows clean Object-Oriented principles.
3. Executor Framework Compatibility: Modern enterprise applications rarely create threads with new Thread(). They use thread pools (ExecutorService), which directly consume Runnable and Callable tasks.
Q2. What is the fundamental difference between Runnable and Callable? ▼
Answer:
• Method Name & Signature: Runnable defines public void run(); Callable<V> defines public V call() throws Exception.
• Return Value: Runnable cannot return a value (it is void). Callable returns a generic type V.
• Checked Exceptions: Runnable.run() cannot declare or throw checked exceptions (must handle internally with try/catch). Callable.call() can throw checked exceptions directly to the caller.
Q3. Can a thread be restarted after it finishes execution? ▼
Answer: No. Once a thread completes its run() method, its state permanently becomes TERMINATED (dead). If you attempt to call t.start() again on the same Thread instance, the JVM throws an IllegalThreadStateException at runtime. To run the same task again, you must instantiate a new Thread object.
Q4. What is FutureTask and why is it used with Callable? ▼
Answer: The java.lang.Thread constructor only accepts a Runnable target; it does not accept a Callable. FutureTask<V> is a concrete class that implements the RunnableFuture<V> interface (which extends both Runnable and Future<V>). It acts as a bridge: you pass your Callable to FutureTask, and because FutureTask is a Runnable, you can pass it to new Thread(futureTask). Once executed, the caller retrieves the returned value using futureTask.get().
Q5. What happens if an unhandled RuntimeException occurs inside a thread's run() method? ▼
Answer: The unhandled exception prints a stack trace to System.err, and that particular thread terminates immediately. However, unless the exception kills the main thread or corrupts shared static state, other independent threads and the JVM continue running normally. You can catch unhandled thread exceptions globally using Thread.setDefaultUncaughtExceptionHandler().

📌 Core Summary & Key Takeaways

  • Extending Thread: Simplest approach; override run(). Limited because Java disallows multiple class inheritance.
  • Implementing Runnable: Best practice standard; separates the task logic from the thread worker. Clean, multiple-inheritance friendly, and works with Java 8+ lambdas.
  • Implementing Callable: Solves Runnable's limits by returning a generic value and throwing checked exceptions. Wrapped in FutureTask when executed with standard threads.
  • start() vs run(): Always call .start() to allocate an operating system thread. Calling .run() directly only executes synchronously on the current caller thread.
  • One-Time Lifecycle: A thread cannot be restarted once started. Calling start() twice throws IllegalThreadStateException.
