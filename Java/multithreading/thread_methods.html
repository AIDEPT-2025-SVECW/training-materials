1. Catalog of Foundational Thread Control Methods

Quick Overview

The java.lang.Thread class provides control methods to orchestrate how and when threads execute. Notice carefully whether each method is static (operates on the current calling thread) or an instance method (operates on a specific target thread object):

Method Type What it Does Throws Checked Exception?
t.start() Instance Allocates native OS thread resources and schedules the JVM to call run(). No (Throws IllegalThreadStateException if called twice)
t.run() Instance Contains the target task code. If called directly, executes synchronously on the calling thread! No
Thread.sleep(ms) Static Temporarily halts the currently executing thread for specified milliseconds. Does NOT release locks. Yes: InterruptedException
t.join() Instance Causes the calling thread to pause and wait until thread t terminates. Yes: InterruptedException
Thread.yield() Static A voluntary hint to the CPU scheduler that the current thread is willing to yield its time slice. No
t.interrupt() Instance Signals thread t to stop or wake up. Wakes sleeping/waiting threads with InterruptedException. No

2. start() vs. run(): The Most Critical Rule

#1 Interview Question

Students frequently confuse start() with run(). Here is the single golden rule:

✓ Calling t.start()

1. Requests an operating system thread from the kernel.
2. Creates a new private call stack.
3. Changes thread state to RUNNABLE.
4. Asynchronously invokes run() on the new thread!

✗ Calling t.run() Directly

1. No new thread is spawned!
2. No new call stack is created.
3. Executes sequentially on the caller thread (e.g., main) like any ordinary method call!
4. Defeats the entire purpose of multi-threading.

StartVsRunDemo.java
public class StartVsRunDemo {
    public static void main(String[] args) {
        Thread t = new Thread(() -> {
            System.out.println("Task is running on: " + Thread.currentThread().getName());
        }, "MyWorkerThread");

        // Test 1: Calling run() directly
        System.out.println("Calling .run() directly:");
        t.run(); // Runs on 'main'!

        // Test 2: Calling start()
        System.out.println("\nCalling .start():");
        t.start(); // Spawns 'MyWorkerThread'!
    }
}
Calling .run() directly: Task is running on: main Calling .start(): Task is running on: MyWorkerThread

3. Thread.sleep(millis): Pausing Execution

Timed Pause

Thread.sleep(long millis) pauses the currently executing thread for the specified number of milliseconds (1000 ms = 1 second).

⚠️
Two Essential Rules for sleep():
1. It is a static method: It ALWAYS pauses whichever thread invokes it. Calling t1.sleep(500) does NOT put t1 to sleep; it puts the current thread to sleep!
2. Throws InterruptedException: Because another thread can wake a sleeping thread early via interrupt(), Thread.sleep() is a checked exception and must be wrapped in a try-catch block.
SleepExample.java
public class SleepExample {
    public static void main(String[] args) {
        Thread worker = new Thread(() -> {
            System.out.println("Worker: Going to sleep for 500 ms...");
            try {
                Thread.sleep(500); // Pauses for 0.5 seconds
            } catch (InterruptedException e) {
                System.out.println("Worker was woken up early!");
            }
            System.out.println("Worker: Woke up! Resuming work.");
        });

        worker.start();
    }
}
Worker: Going to sleep for 500 ms... (0.5 second pause) Worker: Woke up! Resuming work.

4. thread.join(): Waiting for a Thread to Finish

Coordination

When you spawn a child thread, the main thread continues running independently. If the main thread needs the child thread's work to finish before proceeding, it calls childThread.join().

💡
The Simple Analogy:
"Thread A calls threadB.join() means: Thread A pauses right here and waits until Thread B is completely done before continuing."
JoinExample.java
public class JoinExample {
    public static void main(String[] args) throws InterruptedException {
        Thread child = new Thread(() -> {
            System.out.println("Child: Step 1 starting...");
            System.out.println("Child: Step 2 starting...");
            System.out.println("Child: All steps completed!");
        });

        System.out.println("Main: Starting child thread...");
        child.start();

        System.out.println("Main: Calling child.join()... Main will wait here!");
        child.join(); // Main thread pauses right here until child finishes!

        System.out.println("Main: Resumed! Child thread is finished. Main can exit now.");
    }
}
Main: Starting child thread... Main: Calling child.join()... Main will wait here! Child: Step 1 starting... Child: Step 2 starting... Child: All steps completed! Main: Resumed! Child thread is finished. Main can exit now.

5. Thread.yield(): Polite Cooperation Hint

CPU Scheduling

Thread.yield() is a static method that provides a voluntary hint to the operating system thread scheduler:

🗣️
"I have completed part of my computation. If there are other threads of equal priority waiting for CPU time, they can take a turn now."

Key Behavioral Properties:

  • Non-Deterministic: It is purely a hint! The OS scheduler is completely free to ignore it.
  • Remains RUNNABLE: Does not cause the thread to sleep or block. It moves from RUNNING back to the ready RUNNABLE queue.
YieldSnippet.java
for (int i = 1; i <= 3; i++) {
    System.out.println(Thread.currentThread().getName() + " -> " + i);
    Thread.yield(); // Give other threads a turn
}

6. thread.interrupt(): Safe Thread Interruption

Safe Thread Cancellation

In older versions of Java, developers called thread.stop() to kill a thread. However, stop() was deprecated because it forcefully killed threads, unlocking shared data mid-operation and leaving memory corrupted! Today, interrupt() is the official, safe mechanism.

How interrupt() Operates in Two Scenarios:

Scenario A: Thread is Sleeping / Waiting

If the thread is currently inside Thread.sleep() or thread.join(), calling interrupt() immediately terminates the sleep and throws an InterruptedException so the thread can clean up and exit gracefully.

Scenario B: Thread is Actively Computing

If the thread is in a standard loop, calling interrupt() sets an internal boolean flag to true. The thread periodically checks Thread.currentThread().isInterrupted() and terminates itself cleanly.

InterruptExample.java
public class InterruptExample {
    public static void main(String[] args) throws InterruptedException {
        Thread worker = new Thread(() -> {
            System.out.println("Worker: Sleeping for 4 seconds...");
            try {
                Thread.sleep(4000);
                System.out.println("Worker: Finished sleep normally.");
            } catch (InterruptedException e) {
                System.out.println("Worker: Interrupted! Woke up early. Safely exiting.");
            }
        });

        worker.start();

        Thread.sleep(200); // Let worker go to sleep
        System.out.println("Main: Sending interrupt signal to worker...");
        worker.interrupt(); // Wakes up worker immediately!
    }
}
Worker: Sleeping for 4 seconds... Main: Sending interrupt signal to worker... Worker: Interrupted! Woke up early. Safely exiting.

8. Complete Verified Java Demo: ThreadMethodsDemo.java

Verified Java 17 Demo

The following complete program tests all 5 methods with simple, predictable console prints:

ThreadMethodsDemo.java
/**
 * Thread Execution & Control Methods Demonstration
 * 
 * Demonstrates the 5 foundational thread control methods:
 * 1. start() vs run()
 * 2. Thread.sleep(millis)
 * 3. thread.join()
 * 4. Thread.yield()
 * 5. thread.interrupt()
 */
public class ThreadMethodsDemo {

    public static void main(String[] args) throws InterruptedException {
        System.out.println("==========================================================");
        System.out.println("     THREAD EXECUTION & CONTROL METHODS DEMONSTRATION     ");
        System.out.println("==========================================================");

        // ---------------------------------------------------------------------
        // 1. start() vs run()
        // ---------------------------------------------------------------------
        System.out.println("\n--- 1. Testing start() vs run() ---");
        Thread directRunThread = new Thread(() -> {
            System.out.println("  [directRunThread] Executing on: " + Thread.currentThread().getName());
        });

        System.out.println("Calling .run() directly:");
        directRunThread.run(); // Runs on main thread! No new thread created.

        Thread actualThread = new Thread(() -> {
            System.out.println("  [actualThread] Executing on: " + Thread.currentThread().getName());
        }, "Worker-NewThread");

        System.out.println("Calling .start():");
        actualThread.start(); // Spawns new thread Worker-NewThread!
        actualThread.join();

        // ---------------------------------------------------------------------
        // 2. Thread.sleep()
        // ---------------------------------------------------------------------
        System.out.println("\n--- 2. Testing Thread.sleep(400) ---");
        Thread sleeper = new Thread(() -> {
            System.out.println("  [Sleeper] Thread started. Going to sleep for 400 ms...");
            try {
                Thread.sleep(400);
            } catch (InterruptedException e) {
                System.out.println("  [Sleeper] Woken up early!");
            }
            System.out.println("  [Sleeper] Woke up! Finished sleep.");
        }, "SleeperThread");

        sleeper.start();
        sleeper.join();

        // ---------------------------------------------------------------------
        // 3. thread.join()
        // ---------------------------------------------------------------------
        System.out.println("\n--- 3. Testing thread.join() ---");
        Thread childThread = new Thread(() -> {
            System.out.println("  [ChildThread] Step 1 starting...");
            try { Thread.sleep(200); } catch (InterruptedException ignored) {}
            System.out.println("  [ChildThread] Step 2 starting...");
            try { Thread.sleep(200); } catch (InterruptedException ignored) {}
            System.out.println("  [ChildThread] All steps completed!");
        }, "ChildThread");

        System.out.println("Main: Starting childThread...");
        childThread.start();
        System.out.println("Main: Calling childThread.join()... Main is waiting!");
        childThread.join(); // Main thread pauses right here until childThread finishes!
        System.out.println("Main: Resumed! Child thread has completed.");

        // ---------------------------------------------------------------------
        // 4. Thread.yield()
        // ---------------------------------------------------------------------
        System.out.println("\n--- 4. Testing Thread.yield() ---");
        Runnable yieldTask = () -> {
            for (int i = 1; i <= 3; i++) {
                System.out.println("  [" + Thread.currentThread().getName() + "] Count: " + i);
                Thread.yield(); // Voluntary hint to CPU scheduler
            }
        };

        Thread y1 = new Thread(yieldTask, "YieldThread-A");
        Thread y2 = new Thread(yieldTask, "YieldThread-B");
        y1.start();
        y2.start();
        y1.join();
        y2.join();

        // ---------------------------------------------------------------------
        // 5. thread.interrupt()
        // ---------------------------------------------------------------------
        System.out.println("\n--- 5. Testing thread.interrupt() ---");
        Thread sleepingWorker = new Thread(() -> {
            System.out.println("  [InterruptWorker] Sleeping for 4000 ms (4 seconds)...");
            try {
                Thread.sleep(4000);
                System.out.println("  [InterruptWorker] Finished sleep normally.");
            } catch (InterruptedException e) {
                System.out.println("  [InterruptWorker] Received interrupt! InterruptedException caught.");
                System.out.println("  [InterruptWorker] Safely exiting early.");
            }
        }, "InterruptWorker");

        sleepingWorker.start();
        Thread.sleep(200); // Give worker 200ms to enter sleep
        System.out.println("Main: Calling sleepingWorker.interrupt()...");
        sleepingWorker.interrupt();
        sleepingWorker.join();

        System.out.println("\n==========================================================");
        System.out.println("All thread control methods tested successfully!");
        System.out.println("==========================================================");
    }
}

9. Deprecated Thread Methods: Why You Must Never Use Them

Crucial Anti-Patterns
Deprecated Method Why it Was Banned / Deprecated Modern Safe Alternative
thread.stop() Forces the thread to die instantly and unlocks all monitored locks. If an object was mid-modification, it is left corrupted and invalid. Use thread.interrupt() and check isInterrupted() to exit gracefully.
thread.suspend() Freezes a thread without releasing any locks. If the thread holding the lock needed to resume it is blocked, instant deadlock occurs! Use wait() and notify() or LockSupport.park().
thread.resume() Direct counterpart of suspend(), inherently deadlock-prone. Use notify() / notifyAll() or LockSupport.unpark().

10. Frequently Asked Questions & Interview Concepts

Interview Preparation

Click any question to reveal the comprehensive interview-grade answer:

Q1. What is the fundamental difference between Thread.sleep() and Object.wait()? ▼
Answer: This is one of Java's most famous interview questions:
• Class & Method: sleep() is a static method in java.lang.Thread. wait() is an instance method in java.lang.Object.
• Lock Behavior: Thread.sleep() never releases locks (if inside a synchronized block, other threads remain locked out). wait() temporarily releases the object monitor lock so other waiting threads can acquire it.
• Waking Up: sleep() wakes up after time expires or via interrupt(). wait() wakes up when another thread calls notify() / notifyAll() on the same object.
Q2. Can one thread put another thread to sleep by calling t2.sleep(1000)? ▼
Answer: No! Thread.sleep() is a static method. Even if written as t2.sleep(1000), the Java compiler resolves it statically as Thread.sleep(1000). It will put whichever thread is currently executing that statement to sleep, NOT t2!
Q3. What happens if join() is called on a thread that has not started or is already dead? ▼
Answer: The join() method checks isAlive() internally. If the target thread has not been started yet, or if it has already finished executing, isAlive() returns false and join() returns immediately without pausing the calling thread.
Q4. Why is Thread.yield() described as non-deterministic? ▼
Answer: yield() only sends a polite suggestion to the underlying operating system thread scheduler. The JVM does not enforce scheduling; the OS kernel determines thread dispatching based on priorities and core availability. The scheduler is free to ignore the hint and immediately re-dispatch the exact same thread. Therefore, you should never rely on yield() for critical program synchronization.
Q5. What is the difference between interrupt() and isInterrupted()? ▼
Answer:
• t.interrupt(): Action method that sends the interrupt signal to thread t.
• t.isInterrupted(): Query method that returns true if thread t has been interrupted, without clearing the flag.
• Thread.interrupted(): Static method that tests whether the current thread has been interrupted AND clears the interrupt flag!

📌 Core Summary & Key Takeaways

  • start() creates the thread: Always call .start(). Never call .run() directly unless you want sequential execution on the caller thread.
  • Thread.sleep() pauses current thread: Static method; holds all locks; throws checked InterruptedException.
  • thread.join() synchronizes completion: The calling thread blocks and waits until the target thread finishes execution.
  • Thread.yield() gives other threads a chance: Voluntary hint; does not block; thread remains in RUNNABLE queue.
  • thread.interrupt() is the modern stop: Wakes sleeping threads via InterruptedException and allows graceful, clean shutdown without resource leaks.
