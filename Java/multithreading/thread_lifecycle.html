1. The Six States Defined in java.lang.Thread.State

Standard Enum

In Java, thread states are strictly defined in the java.lang.Thread.State public enum. You can inspect any thread's current state at any moment by invoking: 

Thread.State currentState = thread.getState();
1. NEW State: NEW

The thread object has been created (new Thread()) but start() has not been invoked yet.

2. RUNNABLE State: RUNNABLE

The thread is eligible for CPU execution. It is either actively running or waiting in the OS ready queue.

3. BLOCKED State: BLOCKED

Waiting to acquire a monitor lock to enter or re-enter a synchronized block/method.

4. WAITING State: WAITING

Waiting indefinitely for another thread to perform a specific action (e.g. wait(), join()).

5. TIMED_WAITING State: TIMED_WAITING

Waiting for a specified time period (e.g. sleep(ms), wait(ms), join(ms)).

6. TERMINATED State: TERMINATED

The thread has finished its run() method execution, or died due to an unhandled exception.

3. Deep-Dive: Understanding State Behaviors

Detailed Analysis

1. NEW

• How it enters: When you execute Thread t = new Thread(task);.
• State of the thread: Merely a regular Java heap object. No operating system execution thread or call stack exists yet!
• How it leaves: Calling t.start() moves it to RUNNABLE.

2. RUNNABLE (Ready + Running)

• Important nuance: Java combines both Ready to Run (waiting in OS queue) and Actively Running (executing on a silicon core) under the single state RUNNABLE.
• Why? The OS scheduler constantly switches threads in microseconds. The JVM leaves CPU scheduling details to the operating system.

3. BLOCKED (Lock Contention)

• How it enters: A thread tries to enter a synchronized method or block, but another thread already holds the monitor lock.
• CPU Consumption: 0% CPU. The thread is parked by the JVM until the holding thread releases the lock.
• How it leaves: Once the lock is released, the thread re-enters RUNNABLE.

4. WAITING (Indefinite Wait)

• How it enters: Calling object.wait(), thread.join(), or LockSupport.park() without timeouts.
• Behavior: The thread will wait forever until another thread explicitly calls notify(), notifyAll(), or the target joined thread finishes.

5. TIMED_WAITING (Timed Pause)

• How it enters: Calling Thread.sleep(millis), object.wait(millis), or thread.join(millis).
• Behavior: Wakes up automatically when the timer reaches zero, or when interrupted via interrupt().

6. TERMINATED (Dead)

• How it enters: When the thread's run() method finishes execution, or when an unhandled exception crashes the thread.
• Crucial rule: A terminated thread cannot be restarted. Calling start() again throws IllegalThreadStateException.

5. The Big Comparison: BLOCKED vs. WAITING vs. TIMED_WAITING

Interview Hotspot

Examiners love to ask the difference between the three inactive states. Memorize these distinct roles:

Criteria BLOCKED WAITING TIMED_WAITING
Reason for Waiting Waiting strictly to acquire a synchronized monitor lock. Waiting indefinitely for another thread's signal or completion. Waiting for a specified duration of time.
Typical Triggers Lock contention on entering a synchronized block. object.wait(), thread.join(). Thread.sleep(ms), wait(ms), join(ms).
How it Wakes Up The lock holder leaves the synchronized block and JVM assigns lock. Another thread invokes notify() or target thread completes. Timeout counter expires or interrupt() is called.

6. Complete Verified Java Demo: ThreadLifecycleDemo.java

Verified Java 17 Demo

The following self-contained program programmatically transitions threads through all six states and prints each state using thread.getState():

ThreadLifecycleDemo.java
/**
 * Thread Lifecycle & States Demonstration in Java
 * 
 * Demonstrates the 6 thread states defined in java.lang.Thread.State:
 * 1. NEW
 * 2. RUNNABLE
 * 3. TIMED_WAITING
 * 4. WAITING
 * 5. BLOCKED
 * 6. TERMINATED
 */
public class ThreadLifecycleDemo {

    private static final Object LOCK = new Object();

    public static void main(String[] args) throws InterruptedException {
        System.out.println("==========================================================");
        System.out.println("      JAVA THREAD LIFECYCLE & 6 STATES DEMONSTRATION      ");
        System.out.println("==========================================================");

        // ---------------------------------------------------------------------
        // 1. NEW, RUNNABLE, TIMED_WAITING & TERMINATED
        // ---------------------------------------------------------------------
        System.out.println("\n--- Step 1: NEW, RUNNABLE, TIMED_WAITING & TERMINATED ---");

        Thread t1 = new Thread(() -> {
            try {
                // Thread enters TIMED_WAITING while sleeping
                Thread.sleep(400);
            } catch (InterruptedException ignored) {}
        }, "WorkerThread-1");

        // State 1: NEW (created but start() not called yet)
        System.out.println("  t1 State after instantiation : " + t1.getState()); // NEW

        // State 2: RUNNABLE (start() called, eligible for CPU)
        t1.start();
        System.out.println("  t1 State after start() called: " + t1.getState()); // RUNNABLE

        // Wait 100ms to let t1 enter Thread.sleep()
        Thread.sleep(100);
        // State 3: TIMED_WAITING
        System.out.println("  t1 State while inside sleep(): " + t1.getState()); // TIMED_WAITING

        // Wait for t1 to finish
        t1.join();
        // State 4: TERMINATED
        System.out.println("  t1 State after run() finishes: " + t1.getState()); // TERMINATED

        // ---------------------------------------------------------------------
        // 2. WAITING (Indefinite Wait via join)
        // ---------------------------------------------------------------------
        System.out.println("\n--- Step 2: WAITING State ---");
        Thread helper = new Thread(() -> {
            try {
                Thread.sleep(300);
            } catch (InterruptedException ignored) {}
        }, "HelperThread");

        Thread waiter = new Thread(() -> {
            try {
                // Waits indefinitely for helper thread to finish
                helper.join();
            } catch (InterruptedException ignored) {}
        }, "WaiterThread");

        helper.start();
        waiter.start();

        Thread.sleep(100); // Give waiter time to call helper.join()
        // State 5: WAITING
        System.out.println("  waiter State while inside helper.join(): " + waiter.getState()); // WAITING

        helper.join();
        waiter.join();

        // ---------------------------------------------------------------------
        // 3. BLOCKED (Waiting to acquire synchronized lock)
        // ---------------------------------------------------------------------
        System.out.println("\n--- Step 3: BLOCKED State ---");

        Thread lockHolder = new Thread(() -> {
            synchronized (LOCK) {
                try {
                    // Holds the lock for 500 ms
                    Thread.sleep(500);
                } catch (InterruptedException ignored) {}
            }
        }, "LockHolder");

        Thread lockContender = new Thread(() -> {
            // Attempts to enter synchronized block while lockHolder owns it
            synchronized (LOCK) {
                System.out.println("  LockContender finally acquired lock!");
            }
        }, "LockContender");

        lockHolder.start();
        Thread.sleep(50); // Ensure lockHolder acquires LOCK first

        lockContender.start();
        Thread.sleep(50); // Ensure lockContender tries to acquire LOCK and blocks

        // State 6: BLOCKED
        System.out.println("  lockContender State waiting for lock: " + lockContender.getState()); // BLOCKED

        lockHolder.join();
        lockContender.join();

        System.out.println("\n==========================================================");
        System.out.println("All 6 thread states verified successfully!");
        System.out.println("==========================================================");
    }
}

7. Frequently Asked Questions & Interview Concepts

Interview Preparation

Click any question to reveal the comprehensive interview-grade answer:

Q1. Why does Java not have separate "RUNNING" and "READY" states in Thread.State? ▼
Answer: Modern operating systems use preemptive multithreading where CPU cores execute threads in tiny time-slices (quanta, e.g. 10ms). The OS thread scheduler switches between "ready in queue" and "running on CPU" thousands of times per second. Because this switching occurs at the OS kernel level and changes too rapidly for the JVM to accurately track or report, Java unifies both conditions under a single state: RUNNABLE.
Q2. What is the fundamental difference between BLOCKED and WAITING states? ▼
Answer:
• BLOCKED: A thread is waiting strictly to acquire a monitor lock to enter or re-enter a synchronized block or method. It cannot do anything until another thread leaves the synchronized block.
• WAITING: A thread has voluntarily paused itself by calling wait() or join(). It is not waiting for a lock; it is waiting for another thread to send a signal via notify() / notifyAll() or for the target thread to complete execution.
Q3. Can a thread transition directly from NEW to TERMINATED? ▼
Answer: No. A thread in the NEW state has never been started. It must first transition to RUNNABLE when start() is called. Only after entering RUNNABLE can it execute and eventually transition to TERMINATED upon completing run() or throwing an uncaught exception. If you never call start(), the object is eventually garbage-collected from the Heap as an unstarted object.
Q4. What is the difference between Thread.isAlive() and Thread.getState()? ▼
Answer:
• isAlive() returns a boolean (true if the thread has been started and has not yet died). It returns false for both NEW and TERMINATED threads.
• getState() returns one of the 6 precise enum constants (NEW, RUNNABLE, BLOCKED, WAITING, TIMED_WAITING, TERMINATED), allowing detailed diagnostic inspection.
Q5. Does a thread in the TIMED_WAITING state release its synchronized locks? ▼
Answer: It depends on the method used:
• If it entered TIMED_WAITING via Thread.sleep(ms), it retains all acquired locks. No other thread can access those synchronized blocks.
• If it entered TIMED_WAITING via object.wait(ms), it temporarily releases the monitor lock on that object while waiting!

📌 Core Summary & Key Takeaways

  • Six Standard States: NEW, RUNNABLE, BLOCKED, WAITING, TIMED_WAITING, TERMINATED.
  • RUNNABLE encompasses both Ready and Running: The JVM lets the OS kernel handle fast preemptive time-slicing.
  • BLOCKED is for locks: Occurs strictly when waiting to enter a synchronized block/method.
  • WAITING vs TIMED_WAITING: WAITING has no deadline; TIMED_WAITING has an automatic expiration countdown.
  • Dead is Dead: Once a thread reaches TERMINATED, it cannot be restarted. Calling start() throws IllegalThreadStateException.
