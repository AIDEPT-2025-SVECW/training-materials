Order Up: Polymorphism, plated two ways

A food-ordering backend needs one placeOrder that works with or without a coupon, and one calculateTax() that behaves differently for a pizza than for a cola. The first is decided by the compiler before the app ever runs. The second is decided by the JVM while the order is being processed. Pick a tab and place some orders to see the difference.

Modeled after the class layout in pradeepjuluri143/FoodOrderingSystem — a Spring Boot + React app built to teach OOP concepts.

Method Overloading — resolved at compile time

OrderService exposes two methods both named placeOrder. The compiler looks only at the method signature — the number and types of arguments you write at the call site — and picks one of them while compiling your code. No order object needs to exist yet, and nothing about it changes the decision. This is static binding.

public class OrderService { // Signature #1 — one argument public Order placeOrder(OrderRequest request) { return placeOrder(request, null); } // Signature #2 — two arguments, second is a coupon code public Order placeOrder(OrderRequest request, String couponCode) { DiscountStrategy strategy = resolveStrategy(couponCode); // ...apply strategy, deduct wallet, create Order } }

Compile-time polymorphism: since only request is passed, the single-argument overload is the only signature that matches. The JVM never has to decide anything — this was locked in before the .class file was written.

Method Overriding — resolved at runtime

FoodItem and BeverageItem both extend the abstract class MenuItem and both override calculateTax(). When code loops over a List<MenuItem> and calls item.calculateTax(), the compiler only knows it's some MenuItem — the JVM checks the object's actual class the moment the line executes and dispatches to the matching override. This is dynamic dispatch.

public abstract class MenuItem { protected double basePrice; public abstract double calculateTax(); } public class FoodItem extends MenuItem { @Override public double calculateTax() { return basePrice * 0.05; } // 5% GST } public class BeverageItem extends MenuItem { @Override public double calculateTax() { return basePrice * 0.12; } // 12% beverage tax } // same line of code, called on a MenuItem reference — behavior depends on the real object for (MenuItem item : cart) { total += item.calculateTax(); }
