Nested Interfaces in Java

Discover inner interface design: interfaces declared inside interfaces vs classes, implicit static rules, access modifier flexibility, and famous JDK patterns like Map.Entry.

1. What is a Nested Interface?

An interface declared inside another interface or class is called a Nested Interface (or Inner Interface). They exist primarily to group logically coupled interfaces and restrict scope without polluting the global package namespace.

Type 1: Interface inside an Interface

Declared inside another interface. Always public static by default. Cannot be marked private or protected.

Type 2: Interface inside a Class

Declared inside a class. Always static by default, but CAN have any access specifier (public, protected, default, or private).

⚖️

2. Rules: Interface-in-Interface vs Interface-in-Class

Characteristic Interface Inside an Interface Interface Inside a Class
Allowed Modifiers Strictly public only (implicit). Any other modifier causes a compile error. Can be public, protected, package-private (default), or private!
Static Nature Always implicitly static. Always implicitly static (no instance needed to implement it).
External Access OuterInterface.InnerInterface OuterClass.InnerInterface
Real-World JDK Example java.util.Map.Entry<K, V> android.view.View.OnClickListener

3. Type 1: Interface Inside an Interface (Map.Entry Pattern)

Here is how the standard Java Collections Framework defines the nested Entry contract inside the top-level Map interface:

CustomMap.java (Interface Inside Interface)
// Outer Interface
interface CustomMap {
    void put(String key, String value);

    // Nested Interface: Implicitly 'public static'
    interface Entry {
        String getKey();
        String getValue();
    }
}

// Implementing class can implement the nested interface directly:
class SimpleEntry implements CustomMap.Entry {
    private String key, value;

    public SimpleEntry(String key, String value) {
        this.key = key;
        this.value = value;
    }

    @Override
    public String getKey() { return key; }

    @Override
    public String getValue() { return value; }
}

4. Type 2: Interface Inside a Class (Event Listener Pattern)

Commonly found in UI frameworks like Android, JavaFX, and Swing. The enclosing widget defines its own listener contract:

UIButton.java (Widget with Nested Interface)
class UIButton {
    private String label;

    // Nested Interface inside class: Can be public, protected, package-private, or private
    public interface OnClickListener {
        void onClick(UIButton button);
    }

    private OnClickListener listener;

    public UIButton(String label) { this.label = label; }

    public void setOnClickListener(OnClickListener listener) {
        this.listener = listener;
    }

    public void triggerClick() {
        System.out.println("Button '" + label + "' tapped!");
        if (listener != null) listener.onClick(this);
    }
}
NestedInterfaceDemo.java (Driver & Output)
public class NestedInterfaceDemo {
    public static void main(String[] args) {
        UIButton loginBtn = new UIButton("Sign In");

        // Implement the nested interface using Lambda expression:
        loginBtn.setOnClickListener(btn ->
            System.out.println("Authenticated user & redirecting to dashboard.")
        );

        loginBtn.triggerClick();
    }
}
