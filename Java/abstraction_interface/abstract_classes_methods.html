Abstract Classes & Abstract Methods

Explore partial abstraction in Java: how abstract classes define partial templates, why constructors exist in uninstantiable classes, and which method modifier combinations are strictly forbidden by javac.

🔑 abstract Keyword ⚙️ Template Method Pattern 🚫 Forbidden Combinations
🧱

1. Fundamentals: Syntax and Anatomy

An Abstract Class is a class that serves as an incomplete blueprint for subclasses. It cannot be instantiated on its own. An Abstract Method is a method that has only a declaration (signature and return type) without an implementation body.

Vehicle.java (Abstract Class Blueprint)
// 1. Declaring an Abstract Class using the 'abstract' keyword
abstract class Vehicle {
    // Concrete instance variable (State is allowed!)
    protected String brand;
    protected int currentSpeed;

    // Constructor (Allowed! Invoked via super() from child classes)
    public Vehicle(String brand) {
        this.brand = brand;
        this.currentSpeed = 0;
    }

    // 2. Abstract Method: Ends with semicolon; NO curly braces {}
    abstract void accelerate(int rate);
    abstract void applyBrakes();

    // 3. Concrete Method: Shared implementation for all subclasses
    public void displayInfo() {
        System.out.println("Vehicle Brand: " + brand + ", Speed: " + currentSpeed + " km/h");
    }
}
📜

2. The 8 Critical Rules of Abstract Classes

RULE 1
Cannot Be Instantiated Directly: You cannot create an object using new MyAbstractClass(). The Java compiler will flag a compilation error: "Vehicle is abstract; cannot be instantiated".
RULE 2
Can Have Constructors: Even though you cannot instantiate it directly, an abstract class CAN (and often should) have constructors. When a concrete subclass is instantiated with new Car(), the constructor of the abstract parent class executes first via super().
RULE 3
Can Have Both Abstract & Concrete Methods: Unlike pure interfaces (pre-Java 8), an abstract class can mix 0 to 100% abstract methods with fully implemented concrete methods.
RULE 4
Any Abstract Method Forces Class to Be Abstract: If a class contains even a single abstract method, the class itself MUST be declared with the abstract keyword. Otherwise, javac throws an error.
RULE 5
Subclasses Must Implement All Abstract Methods: The first non-abstract (concrete) subclass that extends an abstract class MUST override and provide bodies for ALL inherited abstract methods. If it fails to implement even one, the subclass itself MUST be declared abstract.
RULE 6
Can Have State, Static & Final Members: Abstract classes can contain instance variables, static variables, final variables, static methods, and final methods.
RULE 7
Can Have Zero Abstract Methods: An abstract class does NOT require any abstract methods. You can declare a class abstract purely to prevent other developers from directly instantiating it!
RULE 8
Can Have a main() Method: An abstract class can have a public static void main(String[] args) method and can be executed directly from the terminal or IDE!
🚫

3. Illegal Modifier Combinations on Abstract Methods

This is one of the top interview trick topics. The abstract keyword on a method requires child classes to override it. Any modifier that prevents overriding creates an illegal paradox:

❌ abstract final

Contradiction: abstract demands that a subclass overrides the method. final explicitly prohibits method overriding. Javac Error: "illegal combination of modifiers: abstract and final".

❌ abstract private

Contradiction: private members are completely invisible to subclasses. A child class cannot override a method it cannot see! Javac Error: "illegal combination of modifiers: abstract and private".

❌ abstract static

Contradiction: static methods belong to class memory and participate in compile-time method hiding, NOT runtime dynamic dispatch (polymorphic overriding). Javac Error: "illegal combination of modifiers: abstract and static".

❌ abstract synchronized / native

Contradiction: synchronized and native are implementation details (locks and C/C++ machine bindings). Since an abstract method has NO body, declaring how its nonexistent body is synchronized or native is meaningless.

5. Complete Working Code: Shape & Geometry Hierarchy

Explore the end-to-end executable Java example below, modularly fragmented into its base blueprint, concrete subclasses, and polymorphic execution driver:

Shape.java (Base Abstract Class)
// Base Abstract Class: Defines contract, shared state & template method
abstract class Shape {
    protected String color;

    // Constructor in abstract class (Invoked via super(color) in child classes)
    public Shape(String color) {
        this.color = color;
    }

    // Abstract methods: Subclasses MUST implement these
    abstract double calculateArea();
    abstract double calculatePerimeter();

    // Concrete Template Method: Shared reusable logic across all shapes
    public void printReport() {
        System.out.printf("[%s %s] Area: %.2f | Perimeter: %.2f%n",
                color, getClass().getSimpleName(), calculateArea(), calculatePerimeter());
    }
}
Circle.java (Concrete Subclass)
// Concrete Subclass: Circle
class Circle extends Shape {
    private double radius;

    public Circle(String color, double radius) {
        super(color); // Calls abstract parent's constructor
        this.radius = radius;
    }

    @Override
    double calculateArea() {
        return Math.PI * radius * radius;
    }

    @Override
    double calculatePerimeter() {
        return 2 * Math.PI * radius;
    }
}
Rectangle.java (Concrete Subclass)
// Concrete Subclass: Rectangle
class Rectangle extends Shape {
    private double width, height;

    public Rectangle(String color, double width, double height) {
        super(color);
        this.width = width;
        this.height = height;
    }

    @Override
    double calculateArea() {
        return width * height;
    }

    @Override
    double calculatePerimeter() {
        return 2 * (width + height);
    }
}
ShapeDemo.java (Driver & Output)
public class ShapeDemo {
    public static void main(String[] args) {
        // Polymorphic references using the Abstract Parent type
        Shape c = new Circle("Ruby Red", 5.0);
        Shape r = new Rectangle("Sky Blue", 4.0, 6.0);

        c.printReport(); // [Ruby Red Circle] Area: 78.54 | Perimeter: 31.42
        r.printReport(); // [Sky Blue Rectangle] Area: 24.00 | Perimeter: 20.00

}
