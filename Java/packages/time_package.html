1. PRE-JAVA 8 ERA: What Classes Were Available for Dates?

Before Java 8 introduced the modern java.time package (JSR-310 in 2014), date and time handling in Java relied on an older, fragmented set of classes across java.util, java.text, and java.sql:

java.util.Date (Java 1.0)

📅 Date

The original date class. Stores milliseconds passed since Unix Epoch (January 1, 1970, 00:00:00 GMT).

⚠️ Problems: Mutable state; represents both date & time despite its name; years were offset from 1900 (year 2026 was 126!) and months were 0-indexed (Jan = 0).

java.util.Calendar (Java 1.1)

🗓️ Calendar & GregorianCalendar

Introduced to perform date arithmetic (adding/subtracting days/months) and handle timezones and calendar conversions via Calendar.getInstance().

⚠️ Problems: Still fully mutable; clunky constant-based syntax (cal.add(Calendar.DATE, 5)); kept the confusing 0-indexed months (0 = Jan, 11 = Dec).

java.text.SimpleDateFormat (Java 1.1)

📝 SimpleDateFormat

The standard legacy utility used to format Date objects into human-readable strings (e.g. "dd-MM-yyyy") and parse strings back to dates.

⚠️ Problems: Not thread-safe! Sharing an instance across threads in multi-threaded web applications produced corrupted dates or random runtime exceptions.

java.sql.* (Java 1.1)

🗄️ SQL Date, Time & Timestamp

JDBC database bridges: java.sql.Date (date only, zeroed time), java.sql.Time (time only), and java.sql.Timestamp (nanosecond precision).

⚠️ Problems: Subclassed java.util.Date but altered behavior; developers frequently imported the wrong package by mistake.

💡 Why Should You Still Know Pre-Java 8 Classes?
Even though modern Java applications use java.time, millions of existing enterprise projects, legacy libraries, and JDBC database drivers still use Date, Calendar, and SimpleDateFormat. You will frequently encounter them in industry code and interview questions!

📜 Code Example: How Dates Were Handled Before Java 8

PreJava8DateDemo.java (Legacy Date API)
import java.util.Date;
import java.util.Calendar;
import java.text.SimpleDateFormat;

public class PreJava8DateDemo {
    public static void main(String[] args) throws Exception {
        // 1. java.util.Date (Stores milliseconds since Jan 1, 1970)
        Date now = new Date();
        System.out.println("1. Current Date: " + now);

        // 2. java.util.Calendar (Used for date calculations)
        Calendar cal = Calendar.getInstance();
        cal.setTime(now);
        cal.add(Calendar.DATE, 5); // Add 5 days

        // Notice the confusing 0-indexed month (0 = January, 10 = November)
        System.out.println("2. Future Date (+5 days): " + cal.getTime());
        System.out.println("   Year: " + cal.get(Calendar.YEAR) + ", Month index (0-based): " + cal.get(Calendar.MONTH));

        // 3. java.text.SimpleDateFormat (Formatting - NOT thread-safe!)
        SimpleDateFormat sdf = new SimpleDateFormat("dd-MM-yyyy HH:mm:ss");
        String formattedDate = sdf.format(cal.getTime());
        System.out.println("3. Formatted Date: " + formattedDate);
    }
}
🖥️ Console Output:
1. Current Date: Mon Nov 02 05:29:04 IST 2026 2. Future Date (+5 days): Sat Nov 07 05:29:04 IST 2026 Year: 2026, Month index (0-based): 10 3. Formatted Date: 07-11-2026 05:29:04

💥 The 3 Fatal Flaws That Led to Java 8 (java.time)

💥 Mutable State

Date and Calendar objects are mutable! If thread A inspects an invoice date while thread B calls date.setTime(), data becomes silently corrupted.

🤯 Confusing Offsets

In Date, years began at 1900 (so 2026 was 126!), and months were 0-indexed (January was 0, December was 11). Countless production bugs resulted from this design.

🧵 Thread-Safety Nightmare

SimpleDateFormat was not thread-safe. Reusing an instance across requests in a Spring Boot or Servlet backend caused random multi-threaded crashes.

2. WHAT: Core Classes in java.time

📅 LocalDate & LocalTime

LocalDate: Date without time or timezone (e.g., Indian Republic Day: 2026-01-26).
LocalTime: Time without date or timezone (e.g., IRCTC Tatkal opening: 10:00:00).

🗓️ LocalDateTime & ZonedDateTime

LocalDateTime: Combines date and time without timezone.
ZonedDateTime: Full date, time, and timezone context with offset: ZoneId.of("Asia/Kolkata") (IST +05:30).

3. HOW: IRCTC Tatkal Train Booking Countdown Scheduler

Tatkal tickets in Indian Railways open at 10:00 AM IST for AC classes and 11:00 AM IST for Non-AC classes one day prior to journey date:

IrctcTatkalScheduler.java
package in.gov.irctc.time;

import java.time.LocalDate;
import java.time.LocalTime;
import java.time.LocalDateTime;
import java.time.ZonedDateTime;
import java.time.ZoneId;
import java.time.Duration;

public class IrctcTatkalScheduler {
    public static void main(String[] args) {
        ZoneId istZone = ZoneId.of("Asia/Kolkata");

        // 1. Current clock in Indian Standard Time (IST)
        ZonedDateTime nowInIndia = ZonedDateTime.now(istZone);
        System.out.println("🕒 Current Clock in India: " + nowInIndia);

        // 2. Journey planned for tomorrow
        LocalDate journeyDate = LocalDate.now(istZone).plusDays(1);
        System.out.println("🚆 Journey Date: " + journeyDate);

        // 3. AC Tatkal opens today at exactly 10:00:00 AM IST
        LocalTime tatkalAcOpenTime = LocalTime.of(10, 0, 0);
        ZonedDateTime acTatkalOpening = ZonedDateTime.of(
                LocalDate.now(istZone), tatkalAcOpenTime, istZone);

        // 4. Calculate countdown Duration
        if (nowInIndia.isBefore(acTatkalOpening)) {
            Duration countdown = Duration.between(nowInIndia, acTatkalOpening);
            long minutesLeft = countdown.toMinutes();
            System.out.println("⏳ AC Tatkal window opens in: " + minutesLeft + " minutes!");
        } else {
            System.out.println("🟢 AC Tatkal booking is currently OPEN for today's quota!");
        }
    }
}

📌 Key Takeaways

  • Pre-Java 8 Legacy: Date, Calendar, and SimpleDateFormat were flawed due to mutability, confusing 0-indexed months, and concurrency bugs.
  • Modern Java 8+ (java.time): Completely replaced legacy classes with clean, immutable, and 100% thread-safe types (JSR-310).
  • Core Classes: LocalDate, LocalTime, LocalDateTime, and ZonedDateTime cleanly model human date concepts.
  • Formatting & Timezones: Use thread-safe DateTimeFormatter (replaces SimpleDateFormat) and ZoneId.of("Asia/Kolkata") for Indian Standard Time operations.
