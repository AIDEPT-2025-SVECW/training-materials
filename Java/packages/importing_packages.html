Importing Packages and Classes into Programs

Understand the import statement, single vs wildcard imports, compiler mechanics, static imports, and resolving real-world naming conflicts.

📥 import Statement ⚡ Static Imports 🔀 Conflict Resolution
❓

1. WHY: Why Do We Need the import Statement?

To use a class from another package without an import statement, you would have to write its Fully Qualified Class Name (FQCN) every single time:

Ugly & Tedious (Without Import)
// Cluttered and painful to read:
java.util.Scanner sc = new java.util.Scanner(java.lang.System.in);
java.util.List<java.lang.String> stations = new java.util.ArrayList<>();

The import statement tells the compiler: "Whenever you see Scanner, look inside java.util to find its definition." This allows clean, readable code: Scanner sc = new Scanner(System.in);

💡
Busting a Common Myth: In Java, import does NOT load bytecode into RAM at runtime (unlike C's #include which literally pastes code, or Python's import which executes module code). An import statement is merely a compile-time typing convenience for the compiler's symbol table lookup.
💡

2. WHAT: The 3 Flavors of Import

1. Explicit Single Class Import

Imports exactly one class:

import java.util.ArrayList;

✅ Best practice in enterprise code; crystal clear dependencies.

2. Package-Level Wildcard Import

Imports all public classes in that package:

import java.util.*;

⚡ Zero runtime performance penalty. However, can lead to ambiguous collisions.

3. Static Import (Java 5+)

Imports static members directly:

import static java.lang.Math.*;

✨ Call sqrt(x) or PI directly without typing Math. prefix.

🛠️

3. HOW: Resolving Real-World Naming Collisions

Let's look at the classic dilemma encountered when booking a train ticket in the IRCTC Indian Railway Reservation System. Both java.util and java.sql contain a class named Date:

IrctcTicketBooking.java (Name Collision Resolution)
package in.gov.irctc.booking;

// Option 1: Import java.util.Date explicitly
import java.util.Date;
import java.util.List;
import java.util.ArrayList;

// Static import for mathematical calculations
import static java.lang.Math.round;
import static java.lang.Math.max;

public class IrctcTicketBooking {
    private String pnrNumber;
    private Date journeyDate;             // Refers to java.util.Date
    private java.sql.Date dbRecordDate;   // Disambiguated with Full Qualified Name!

    public IrctcTicketBooking(String pnr, Date journeyDate) {
        this.pnrNumber = pnr;
        this.journeyDate = journeyDate;
        // Converting util.Date to sql.Date for Oracle/MySQL database persistence:
        this.dbRecordDate = new java.sql.Date(journeyDate.getTime());
    }

    public double calculateTatkalFare(double baseFare, double tatkalPremium) {
        // Using static imports directly without Math. prefix:
        double total = baseFare + max(tatkalPremium, 150.0);
        return round(total);
    }

    public static void main(String[] args) {
        IrctcTicketBooking ticket = new IrctcTicketBooking("2456789012", new Date());
        double totalFare = ticket.calculateTatkalFare(850.00, 220.00);

        System.out.println("🇮🇳 IRCTC Ticket Booked for PNR: " + ticket.pnrNumber);
        System.out.println("Journey Date: " + ticket.journeyDate);
        System.out.println("Database SQL Date: " + ticket.dbRecordDate);
        System.out.println("Total Fare: ₹ " + totalFare);
    }
}
⚖️
The Ambiguity Rule: If you write import java.util.*; and import java.sql.*;, and then type Date d;, the compiler halts with:
error: reference to Date is ambiguous, both class java.util.Date and class java.sql.Date match
To fix it, explicitly specify the full name: java.sql.Date or import one specifically.

📌 Key Takeaways

  • Why: Eliminates lengthy FQCN typing and makes code readable.
  • What: Compile-time directive supporting single class, wildcard, and static member imports.
  • How: Resolve name collisions by importing one class explicitly and qualifying conflicting classes with their full package name (e.g., java.sql.Date).
