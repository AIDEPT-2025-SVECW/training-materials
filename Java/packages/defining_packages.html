Defining Packages in Java

Master syntax rules, reverse domain conventions, and the professional way to compile and execute packaged classes using the javac -d flag.

📜 package Keyword 📁 Directory Mapping ⚙️ javac -d Compilation
❓

1. WHY: Why Must We Explicitly Define Packages?

If you don't write a package statement at the top of your Java file, the class falls into the Default Package (unnamed package). This causes critical issues in real-world software:

🚫 The Unimportable Trap

Since Java 1.4, classes inside a named package CANNOT import classes from the default package! If your teammate puts User.java in the default package, your in.npci.upi.PaymentService cannot import or use it at all.

📦 Production Deployment Breakdown

Enterprise build systems (Maven, Gradle) and containerized microservices require standard directory layouts. Default package classes cannot be properly packaged into modular JAR files.

💡

2. WHAT: Syntax & Naming Rules

Syntax Pattern
package package_name;
// or hierarchical sub-packages:
package top_domain.organization.project.module;

Crucial Naming Conventions

  • All Lowercase: Package names MUST be entirely in lowercase letters (e.g., in.npci.upi, NOT in.NPCI.UPI) to prevent filename conflicts on case-insensitive operating systems like Windows.
  • Reversed Domain: Begin with your organization's reversed internet domain name:
    🇮🇳 in.gov.irctc.booking (IRCTC Railway Reservation)
    🇮🇳 in.npci.upi.qr (NPCI UPI QR Code Engine)
    🇮🇳 com.zomato.delivery.tracking (Zomato Food Delivery)
  • First Statement Rule: The package statement MUST be the very first non-comment line in the source file. Comments and blank lines are allowed above it.
🛑
Only ONE package declaration: A single Java source file can contain at most one package declaration. Having multiple package statements causes a compilation error.
🛠️

3. HOW: Compiling with javac -d & Running

Let's build a real-world UPI QR payment generator for the Indian payments ecosystem:

src/in/npci/upi/qr/UpiQrGenerator.java
package in.npci.upi.qr;

public class UpiQrGenerator {
    private final String vpa; // Virtual Payment Address (e.g., merchant@okhdfcbank)
    private final String merchantName;

    public UpiQrGenerator(String vpa, String merchantName) {
        this.vpa = vpa;
        this.merchantName = merchantName;
    }

    public String generatePaymentLink(double amountInRupees) {
        // Standard NPCI UPI URI Scheme
        return String.format("upi://pay?pa=%s&pn=%s&am=%.2f&cu=INR",
                vpa, merchantName.replace(" ", "%20"), amountInRupees);
    }

    public static void main(String[] args) {
        UpiQrGenerator qr = new UpiQrGenerator("swiggy@icici", "Swiggy Delivery");
        String upiUri = qr.generatePaymentLink(485.50);

        System.out.println("==========================================");
        System.out.println("🇮🇳 NPCI UPI QR Code Payload Generated:");
        System.out.println(upiUri);
        System.out.println("Ready for PhonePe / GooglePay / Paytm Scan");
        System.out.println("==========================================");
    }
}

The Magic javac -d Flag

Novice developers often try to manually create folders on Windows or Mac. The -d (destination) flag tells javac to create all matching nested folders automatically:

developer@workspace:~$ javac -d bin src/in/npci/upi/qr/UpiQrGenerator.java
✔ javac creates the directory bin/in/npci/upi/qr/ and writes UpiQrGenerator.class

developer@workspace:~$ java -cp bin in.npci.upi.qr.UpiQrGenerator
==========================================
🇮🇳 NPCI UPI QR Code Payload Generated:
upi://pay?pa=swiggy@icici&pn=Swiggy%20Delivery&am=485.50&cu=INR
Ready for PhonePe / GooglePay / Paytm Scan
==========================================
⚠️
The Most Common Java Beginner Trap:
Never navigate inside the folder bin/in/npci/upi/qr/ and run java UpiQrGenerator. The JVM will throw Error: Could not find or load main class UpiQrGenerator because the class's full identity is in.npci.upi.qr.UpiQrGenerator. Always run from the root directory with the Fully Qualified Class Name (FQCN)!

📌 Key Takeaways

  • Why: Prevents unimportable default package classes and supports clean modular builds.
  • What: Defined using package <name>; as the first executable line with lowercase naming convention.
  • How: Compile with javac -d <destination> <source.java> and execute from the root using the full class name java -cp bin package.ClassName.
