Java Access Modifiers in Action

In a production backend like the FoodOrderingSystem, sensitive fields like User.passwordHash or Wallet.balance must be hidden, while service entry points like OrderService.placeOrder() must be exposed. Java's four access levels dictate exactly who can see and modify what across packages.

The Four Access Levels in Java

Access modifiers define the visibility of classes, constructors, fields, and methods. Choosing the tightest possible access level enforces Encapsulation and protects internal state from unauthorized external mutation.

private
Same Class Only
Strict data hiding. Hidden from all other classes, even in the same package or subclasses.
default (package-private)
Same Package Only
No keyword specified. Accessible only by classes within the exact same package.
protected
Package + Subclasses
Accessible within the same package AND by child classes in different packages via inheritance.
public
World Access
Fully accessible from any class in any package across the application codebase.

The Java Access Control Matrix

Use this reference table to evaluate visibility across class boundary levels:

FoodOrderingSystem Package Architecture

Real-world Spring Boot backends structure classes into distinct packages for separation of concerns and security isolation:

com.foodapp.model (Domain Entities) ├── public class User { private String passwordHash; public String email; } └── public class MenuItem { protected double basePrice; } com.foodapp.model.special (Subclass Package) └── public class ComboItem extends MenuItem { // Can access protected basePrice directly! } com.foodapp.service (Business Logic & Package-Private Helpers) ├── public class OrderService { public Order placeOrder() { ... } } └── class InternalInventoryValidator { // Package-private helper: hidden outside service package } com.foodapp.controller (REST API Layer) └── public class OrderController { // Calls public OrderService methods ONLY }
Key Design Principle in FoodOrderingSystem:
Controllers in com.foodapp.controller can only call public methods of OrderService. Internal validation helpers in com.foodapp.service are marked default or private so external layers cannot bypass validation rules!
