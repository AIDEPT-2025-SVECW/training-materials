Hierarchy of Exception Classes

Explore the complete object-oriented inheritance tree of java.lang.Throwable, its branches, and the foundational diagnostic methods provided by Java.

1. WHY: Why Does Exception Handling Use an Inheritance Hierarchy?

In Java, errors and exceptions are not primitive error codes or integer flags (like in C/C++). Instead, every exception is a full-fledged Java Object participating in an inheritance hierarchy.

Because exceptions are classes in an inheritance tree, you can leverage Polymorphism in exception handling. A single catch (IOException e) block can catch FileNotFoundException, SocketException, and EOFException because they are all child classes of IOException!

Direct Exception Subclasses
🔒 CHECKED EXCEPTIONS (Compile-Time Enforced)

Compiler verifies these! Code will not compile without enclosing in try-catch or declaring throws.

java.io.IOException
↳ FileNotFoundException
Specified file missing on hard disk

java.lang.RuntimeException
⚡ UNCHECKED EXCEPTIONS (Compiler Ignores)

Compiler ignores these! They represent programmer logic mistakes. Fix the code rather than masking them.

ArithmeticException Divide by zero integer math (e.g., 10 / 0)
NullPointerException Calling a method or accessing a field on a null reference
ArrayIndexOutOfBoundsException Accessing an array index outside [0, length - 1]
NumberFormatException Parsing non-numeric text with Integer.parseInt()
ClassCastException Attempting to downcast an object to an incompatible type
IllegalArgumentException Method received an inappropriate or illegal argument

4 Key Methods Inherited from java.lang.Throwable:

Every single exception class inherits these 4 powerful diagnostic methods from Throwable:

1. public String getMessage()

Returns a short, human-readable error description (e.g. "/ by zero" or "File config.json not found").

2. public String toString()

Returns the complete Exception class name concatenated with the error message.

3. public void printStackTrace()

Prints the full stack trace (the sequence of method calls, file names, and exact line numbers where the exception originated) to standard error stream.

4. public Throwable getCause()

Returns the underlying cause of this exception (used when wrapping low-level exceptions into high-level business exceptions).

3. HOW: Observing Throwable Methods in Action

Here is a practical Indian banking KYC customer lookup demonstrating how the three primary methods of Throwable inspect an exception:

ThrowableMethodsDemo.java
// Demonstrating getMessage(), toString(), and printStackTrace()
public class ThrowableMethodsDemo {

    public static void searchKycCustomer(String customerAadhaar) {
        // Simulating searching an array of KYC registered users
        String[] registeredUsers = { "Aarav Sharma", "Priya Patel", "Rohan Verma" };

        try {
            System.out.println("Accessing user index [5] in array of size 3...");
            
            // Triggers ArrayIndexOutOfBoundsException
            String user = registeredUsers[5];
            System.out.println("Found: " + user);

        } catch (ArrayIndexOutOfBoundsException ex) {
            System.out.println("\n--- Diagnostic Methods Provided by Throwable ---");

            // 1. getMessage() -> concise reason
            System.out.println("1. ex.getMessage(): " + ex.getMessage());

            // 2. toString() -> Class Name + Message
            System.out.println("2. ex.toString(): " + ex.toString());

            // 3. printStackTrace() -> Complete stack trace with line numbers
            System.out.println("3. ex.printStackTrace() Output below:");
            ex.printStackTrace();
        }
    }

    public static void main(String[] args) {
        searchKycCustomer("9876-5432-1098");
    }
}

📌 Key Takeaways for Freshers

  • Root: java.lang.Throwable is the grand parent of all Errors and Exceptions in Java.
  • Two Main Branches: Error (system failures like OutOfMemory) and Exception (application conditions).
  • Under Exception: RuntimeException and its children form the Unchecked family; all other direct subclasses of Exception form the Checked family.
