1. The 5 Core Keywords at a Glance

try Guarded Block

Encloses code that might throw an exception. Cannot exist alone—must be followed by at least one catch or a finally block.

catch Handler Block

Catches and handles the exception thrown by the matching try block. Receives the exception object as an argument.

finally Clean-Up Block

Guaranteed execution block. Used to close files, database connections, and release memory regardless of whether an exception occurred.

throw Action Verb

Used inside method bodies to explicitly instantiate and throw an exception object: throw new MyException("Error");

throws Method Declaration

Appears in method signatures to declare that the method might pass checked exceptions up to its caller: void pay() throws SQLException.

2. WHAT: Multiple Catch Clauses & The finally Guarantee

Rule of Multiple Catch Clauses (Child First, Parent Last):

A single try block can be followed by multiple catch blocks to handle different exceptions specifically.

✅ Correct Ordering (Specific to General):
try { ... }
catch (ArithmeticException e) { ... } // Child
catch (NullPointerException e) { ... } // Child
catch (Exception e) { ... } // Parent (Fallback)
❌ Compiler Error Trap (Parent First):
try { ... }
catch (Exception e) { ... } // Parent catches all!
catch (ArithmeticException e) { ... } // ERROR: Unreachable code!

The Absolute Guarantee of finally:

  • Case 1: If no exception occurs ➔ finally executes.
  • Case 2: If an exception occurs and is caught ➔ finally executes after the catch block.
  • Case 3: If an exception occurs and is NOT caught ➔ finally executes right before the program crashes.
  • Case 4: Even if try or catch contains an explicit return; statement ➔ finally still executes before the method actually returns!
⚡
When does finally NOT execute?
There are only two rare situations where finally does not execute:
  1. The program explicitly calls System.exit(0);, shutting down the JVM process.
  2. A fatal hardware or operating system crash (sudden power loss, CPU core failure).

Quick Interview Comparison: throw vs throws

Comparison Factor throw Keyword throws Keyword
Usage Location Used inside a method body or block. Used in the method signature (declaration).
What Follows It Followed by an exception instance/object: throw new IOException("..."); Followed by exception class name(s): throws IOException, SQLException
Count Can only throw one exception instance at a time. Can declare multiple comma-separated exception classes.
Role Actually triggers / fires the exception at runtime. Advertises to callers that this method may pass checked exceptions.

3. HOW: State Bank of India (SBI) ATM Cash Withdrawal Simulator

Here is a complete, runnable program demonstrating try, multiple catch clauses, the guaranteed finally block, throw, and throws in an Indian banking context:

SbiAtmSession.java (Indian Banking Architecture)
// Custom Business Exception
class InsufficientBalanceException extends Exception {
    public InsufficientBalanceException(String msg) {
        super(msg);
    }
}

public class SbiAtmSession {

    // Method declares that it may throw custom exception using 'throws':
    public static void withdrawCash(int balance, int requestedAmount) 
            throws InsufficientBalanceException {
        
        System.out.println("Verifying SBI Account Balance: ₹ " + balance);

        if (requestedAmount > balance) {
            // Explicitly throwing exception object using 'throw':
            throw new InsufficientBalanceException(
                "Transaction Failed: Requested ₹ " + requestedAmount + " exceeds balance ₹ " + balance
            );
        }

        // Simulating potential division calculation
        int noteCount500 = requestedAmount / 500;
        System.out.println("✅ Dispensing " + noteCount500 + " notes of ₹ 500.");
    }

    public static void main(String[] args) {
        System.out.println("--- 🏧 Welcome to State Bank of India (SBI) ATM ---");
        System.out.println("Card inserted. Session started.");

        try {
            // Guarded try block: Risky withdrawal operation
            int mySavingsBalance = 3000;
            int withdrawAmt = 5000; // Greater than balance!

            withdrawCash(mySavingsBalance, withdrawAmt);

        } catch (InsufficientBalanceException ex) {
            // Catch 1: Specific custom banking business exception
            System.out.println("⚠️ [SBI ATM Alert]: " + ex.getMessage());

        } catch (ArithmeticException ex) {
            // Catch 2: Specific arithmetic error
            System.out.println("⚠️ [Math Error]: Amount must be a multiple of 500.");

        } catch (Exception ex) {
            // Catch 3: General fallback parent exception (must be LAST)
            System.out.println("⚠️ [General Error]: An unexpected error occurred: " + ex.getMessage());

        } finally {
            // The finally block GUARANTEES cleanup even if an exception happened!
            System.out.println("\n🔒 [CRITICAL FINALLY BLOCK]:");
            System.out.println("1. Ejecting debit card from slot...");
            System.out.println("2. Closing encrypted SBI banking session...");
            System.out.println("3. ATM ready for next customer.");
        }

        System.out.println("--- Thank you for visiting SBI ---");
    }
}

📌 Key Takeaways for Freshers

  • Multiple Catch: Always place child exceptions first and parent Exception last.
  • The finally Block: Always executes—ideal for releasing resources (closing database connections, ejecting ATM cards).
  • throw vs throws: throw is an action used inside a method to throw an object; throws is a declaration in the method header advertising possible exceptions.
