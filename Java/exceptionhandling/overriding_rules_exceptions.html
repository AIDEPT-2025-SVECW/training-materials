2. Linking Inheritance to Exception Handling: Method Overriding Rules w.r.t throws

In the Inheritance & Polymorphism module, you learned that a subclass can override a superclass method to provide a specialized implementation.

💡
Why Do These Rules Exist? (Liskov Substitution Principle):
When writing polymorphic code like RbiBank bank = new SbiBank(); bank.transferMoney();, the caller writes try-catch based only on what RbiBank advertises. If SbiBank were allowed to throw brand new, broader checked exceptions, the caller's catch block would be completely blind to them!
📌 Rule 1: If Superclass Method Declares NO Checked Exception

The subclass overriding method CANNOT declare any Checked Exception. It can only declare Unchecked Exceptions (RuntimeException) or declare no exception at all.

Superclass: void pay() (No throws)
Subclass: void pay() throws IOException ➔ ❌ COMPILE-TIME ERROR!
Subclass: void pay() throws NullPointerException ➔ ✅ VALID (Unchecked)
📌 Rule 2: If Superclass Method Declares a Checked Exception

The subclass overriding method can declare:

  • The SAME exception: e.g., parent throws IOException ➔ child throws IOException.
  • A SUBCLASS (narrower/child) exception: e.g., parent throws IOException ➔ child throws FileNotFoundException.
  • NO exception at all: child doesn't throw anything.
  • CANNOT declare a BROADER (parent) exception: e.g., parent throws FileNotFoundException ➔ child throws IOException or Exception (COMPILE ERROR!).
  • CANNOT declare a NEW checked exception: e.g., parent throws IOException ➔ child throws SQLException (COMPILE ERROR!).
📌 Rule 3: Unchecked Exceptions (RuntimeException) Have Complete Freedom

All overriding rules strictly govern Checked Exceptions. A subclass overriding method can freely declare any Unchecked Exception (like ArithmeticException, NullPointerException, IllegalArgumentException) at any time, even if the superclass method didn't declare it!

🛠️

3. HOW: RBI vs SBI/HDFC Banking Method Overriding Demo

Here is a clean Indian banking example demonstrating legal vs illegal overriding with throws:

RbiOverridingRulesDemo.java
import java.io.IOException;
import java.io.FileNotFoundException;
import java.sql.SQLException;

// 1. Parent Superclass: Reserve Bank of India (RBI) Regulatory Standard
class RbiPaymentGateway {

    // Parent Method A: Declares NO exception
    public void validatePanCard(String panNumber) {
        System.out.println("RBI Base: Validating PAN format.");
    }

    // Parent Method B: Declares Checked Exception (IOException)
    public void processUpiTransfer(int amount) throws IOException {
        System.out.println("RBI Base: Processing UPI transfer of ₹ " + amount);
    }
}

// 2. Child Subclass: State Bank of India (SBI) Implementation
class SbiPaymentGateway extends RbiPaymentGateway {

    // OVERRIDING Method A (Parent had NO throws):
    // ✅ LEGAL: Subclass can declare Unchecked RuntimeException freely!
    @Override
    public void validatePanCard(String panNumber) throws IllegalArgumentException {
        if (panNumber == null || panNumber.length() != 10) {
            throw new IllegalArgumentException("Invalid PAN card length!");
        }
        System.out.println("SBI: PAN validated successfully.");
    }

    // OVERRIDING Method B (Parent declared IOException):
    // ✅ LEGAL: Subclass declares FileNotFoundException (a narrower child of IOException)
    @Override
    public void processUpiTransfer(int amount) throws FileNotFoundException {
        System.out.println("SBI: Reading secure certificate & transferring ₹ " + amount);
    }

    /*
     * ❌ ILLEGAL OVERRIDES (Uncommenting causes COMPILE ERROR):
     *
     * 1. Cannot declare broader parent exception:
     *    public void processUpiTransfer(int amt) throws Exception { }
     *    // Error: Exception is not compatible with throws clause in RbiPaymentGateway
     *
     * 2. Cannot declare completely new checked exception:
     *    public void processUpiTransfer(int amt) throws SQLException { }
     *    // Error: SQLException is not compatible with throws clause in RbiPaymentGateway
     */
}

public class RbiOverridingRulesDemo {
    public static void main(String[] args) {
        System.out.println("--- 🇮🇳 RBI vs SBI Overriding Polymorphism Test ---");

        // Polymorphic upcasting: Parent reference referring to Child object
        RbiPaymentGateway gateway = new SbiPaymentGateway();

        try {
            gateway.validatePanCard("ABCDE1234F");
            gateway.processUpiTransfer(2500);
        } catch (IOException ex) {
            System.out.println("Error caught: " + ex.getMessage());
        }

        System.out.println("--- Finished successfully ---");
    }
}

📌 Master Checklist: Overriding Rules with throws

  • Parent has no throws ➔ Child cannot throw any checked exception.
  • Parent throws Checked Exception ➔ Child can throw Same, Narrower Child, or None. Child never throws Broader or New Checked.
  • Unchecked Exceptions (like NullPointerException, IllegalArgumentException) can be thrown by a child method at any time without restriction.
