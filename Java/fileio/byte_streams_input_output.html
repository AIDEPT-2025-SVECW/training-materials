1. The Foundation: InputStream & OutputStream

InputStream and OutputStream are abstract superclasses. For working with files on your hard drive or SSD, Java provides their two most famous implementations:

Class Direction Primary Purpose Key Methods
FileOutputStream Writing (Out) Writes raw 8-bit bytes from RAM to a disk file. write(int b)
write(byte[] b)
write(byte[] b, int off, int len)
close()
FileInputStream Reading (In) Reads raw 8-bit bytes from a disk file into RAM. read(): returns int (0-255, or -1 at EOF)
read(byte[] b): reads a chunk into buffer
available()
close()
💡
The EOF (-1) Rule Every Fresher Must Remember:
When calling read(), Java returns an int containing the next byte (0 to 255). When it reaches the end of the file (EOF), it returns -1. This is how your while loop knows when to stop reading!
📤

2. Writing Data with FileOutputStream (Overwrite vs Append Mode)

When creating a FileOutputStream, you can choose whether to overwrite the file or append to it:

  • new FileOutputStream("sbi_audit.log") ➔ Overwrite Mode: Clears existing content and starts at byte 0.
  • new FileOutputStream("sbi_audit.log", true) ➔ Append Mode: Keeps existing content and appends new bytes to the end!
SbiAuditLogger.java (Writing Bytes)
import java.io.FileOutputStream;
import java.io.IOException;

public class SbiAuditLogger {

    public static void main(String[] args) {
        
        String logFilePath = "sbi_audit_log.bin";
        String transactionRecord = "TXN#987123 | ₹ 25000 Debited to HDFC UPI | 27-OCT-2026 18:30 IST\n";

        // Using try-with-resources: Auto-closes output stream and flushes OS buffers
        // Note the second parameter 'true': APPEND MODE enabled!
        try (FileOutputStream fos = new FileOutputStream(logFilePath, true)) {
            
            // Convert human String characters into raw byte array
            byte[] byteData = transactionRecord.getBytes();

            // Write the entire byte array to disk in one efficient call
            fos.write(byteData);

            System.out.println("✅ SBI Audit transaction successfully written to disk!");
            System.out.println("Bytes written: " + byteData.length);

        } catch (IOException e) {
            System.out.println("❌ Disk Write Failure: " + e.getMessage());
        }
    }
}

3. Reading Data with FileInputStream (Byte-by-Byte vs Buffer Chunk)

Here are the two ways to read bytes back from disk into memory:

SbiAuditReader.java (Reading Bytes)
import java.io.FileInputStream;
import java.io.IOException;

public class SbiAuditReader {

    public static void main(String[] args) {
        
        String logFilePath = "sbi_audit_log.bin";

        System.out.println("=== Reading SBI Audit Log from Disk ===");

        // try-with-resources: FileInputStream auto-closed safely
        try (FileInputStream fis = new FileInputStream(logFilePath)) {
            
            int byteRead;
            // Loop continues until read() returns -1 (End of File)
            while ((byteRead = fis.read()) != -1) {
                // byteRead contains integer (0 to 255). Cast to char to display:
                System.out.print((char) byteRead);
            }

            System.out.println("\n✅ File reached EOF and closed safely.");

        } catch (IOException e) {
            System.out.println("❌ Read Error: " + e.getMessage());
        }
    }
}

4. High-Performance Binary File Copier (Copying Images & PDFs)

Reading 1 byte at a time for a 50 Megabyte Aadhaar KYC PDF or IRCTC ticket QR code would make 50 million slow disk calls! In professional enterprise Java, we read in buffer chunks (e.g. 4096 or 8192 bytes):

AadhaarQrCodeCopier.java (High Speed Binary Copy)
import java.io.FileInputStream;
import java.io.FileOutputStream;
import java.io.IOException;

public class AadhaarQrCodeCopier {

    public static void main(String[] args) {
        
        String sourceImage = "aadhaar_qr.png";
        String destinationBackup = "aadhaar_qr_backup.png";

        System.out.println("=== 🇮🇳 Fast Binary Byte Stream Copier ===");

        // Opening both source input stream and target output stream simultaneously
        try (FileInputStream in = new FileInputStream(sourceImage);
             FileOutputStream out = new FileOutputStream(destinationBackup)) {

            // 4 Kilobyte (4096 bytes) RAM chunk buffer
            byte[] buffer = new byte[4096];
            int bytesRead;
            long totalBytes = 0;

            // in.read(buffer) fills up to 4096 bytes at a time and returns actual count read
            while ((bytesRead = in.read(buffer)) != -1) {
                // Write exactly 'bytesRead' bytes from buffer to output file
                out.write(buffer, 0, bytesRead);
                totalBytes += bytesRead;
            }

            System.out.println("✅ Copy completed successfully!");
            System.out.println("Total bytes transferred: " + totalBytes + " bytes");

        } catch (IOException e) {
            System.out.println("❌ File Copy Exception: " + e.getMessage());
        }
    }
}
💡
Why out.write(buffer, 0, bytesRead) is Critical:
If your buffer is 4096 bytes, but the final remaining chunk of the file only has 150 bytes, writing the entire buffer would write 150 real bytes + 3946 bytes of garbage trailing data! Using bytesRead writes exactly what was read.

📌 Key Takeaways for Freshers

  • FileOutputStream writes bytes; pass true as the 2nd constructor argument to enable append mode.
  • FileInputStream.read() returns an int containing 0-255, or -1 when end of file is reached.
  • Always read/write binary files using a byte[] buffer (4KB or 8KB) instead of single bytes for speed.
  • Always use try-with-resources to guarantee that file handles and OS sockets are closed promptly.
