1. Stateful Authentication Overview

What is Stateful Authentication?
In stateful authentication, the server generates a unique Session ID upon login, stores session state (user details, roles) in server memory or a database (like Redis / MongoDB), and sends the Session ID back to the browser stored securely inside an HTTP cookie (connect.sid).

2. Step-by-Step Setup Process

Step 1: Install Required NPM Dependencies

To implement stateful authentication in Express.js, we install express-session and cookie-parser: 

npm install express express-session cookie-parser
Package Roles:
  • express-session: Manages sessions in server memory / session store, generates Session IDs, and sets session cookies automatically.
  • cookie-parser: Parses cookies attached to incoming HTTP client request headers into req.cookies.

Step 2: Configure Session Middleware in Server

Configure express-session middleware in your main Express app file (e.g. stateful-app.js or server.js): 

const express = require('express');
const session = require('express-session');
const cookieParser = require('cookie-parser');

const app = express();

// Body Parser & Cookie Parser Middleware
app.use(express.json());
app.use(express.urlencoded({ extended: true }));
app.use(cookieParser());

// Configure Session Middleware
app.use(session({
    secret: 'mySuperSecretKey123', // Secret key to sign the session ID cookie
    resave: false,                 // Don't save session if unmodified
    saveUninitialized: false,      // Don't create session until something is stored
    cookie: {
        maxAge: 1000 * 60 * 60,   // Session expiration (1 hour in milliseconds)
        httpOnly: true,           // Prevents client-side JS (XSS) from reading cookie
        secure: false             // Set to true in production with HTTPS
    }
}));
🔒 Security Alert - HttpOnly Flag:
Always keep httpOnly: true in session cookie configuration! This prevents malicious client-side JavaScript scripts from reading document.cookie, protecting your users against XSS session hijacking attacks.

Step 3: Implement Login Endpoint (POST /login)

When user submits credentials, validate them, store identity in req.session, and Express automatically sets the cookie:

// Mock Database
const users = [
    { id: 1, name: 'Pradeep Juluri', email: 'user@example.com', password: 'password123', role: 'admin' }
];

// POST /login - User Login Endpoint
app.post('/login', (req, res) => {
    const { email, password } = req.body;

    // 1. Find user by email
    const user = users.find(u => u.email === email);
    if (!user) {
        return res.status(401).json({ success: false, message: 'Invalid email or password' });
    }

    // 2. Validate password
    if (user.password !== password) {
        return res.status(401).json({ success: false, message: 'Invalid email or password' });
    }

    // 3. Store user details in session object
    req.session.userId = user.id;
    req.session.userEmail = user.email;
    req.session.userRole = user.role;

    // Express-session automatically creates session & sets Set-Cookie: connect.sid=...
    res.json({
        success: true,
        message: 'Login successful! Session initialized.',
        user: { id: user.id, name: user.name, email: user.email, role: user.role }
    });
});

Step 4: Create Authentication Middleware (isAuthenticated)

Create a custom middleware to verify that incoming requests contain an active session before granting access to protected routes:

// Authentication Middleware
const isAuthenticated = (req, res, next) => {
    // Check if session object exists and contains userId
    if (req.session && req.session.userId) {
        return next(); // User authenticated! Proceed to route handler
    }

    // No active session found
    res.status(401).json({
        success: false,
        message: 'Unauthorized access. Please log in first!'
    });
};

module.exports = isAuthenticated;
How Session Lookup Works:
When browser makes a request, it automatically includes Cookie: connect.sid=s%3A.... The express-session middleware extracts the ID, looks up the session in memory store, and populates req.session automatically before reaching isAuthenticated!

Step 5: Protected Routes & Logout Endpoint (POST /logout)

Apply isAuthenticated middleware to protected endpoints, and handle logout by destroying session and clearing cookies:

// GET /dashboard - Protected Route
app.get('/dashboard', isAuthenticated, (req, res) => {
    res.json({
        success: true,
        message: `Welcome to Secret Dashboard, ${req.session.userEmail}!`,
        sessionDetails: {
            userId: req.session.userId,
            role: req.session.userRole,
            sessionExpiry: req.session.cookie.maxAge / 1000 + ' seconds'
        }
    });
});

// POST /logout - Destroy Session & Clear Cookie
app.post('/logout', (req, res) => {
    // 1. Destroy session on server
    req.session.destroy((err) => {
        if (err) {
            return res.status(500).json({ success: false, message: 'Could not log out' });
        }

        // 2. Clear connect.sid cookie on client browser
        res.clearCookie('connect.sid');

        res.json({
            success: true,
            message: 'Logged out successfully. Session destroyed and cookie cleared.'
        });
    });
});

👨‍🏫 Instructor Teaching Notes & Key Takeaways
  • Stateful vs Stateless Distinction: Emphasize that in stateful auth, the server MUST maintain state in memory/Redis. If server restarts, in-memory sessions are wiped (which is why Redis/Mongo store is used in production).
  • Cookie Security Parameters:
    • httpOnly: true (Mitigates XSS)
    • secure: true (Requires HTTPS, set to false in local dev)
    • sameSite: 'strict' (Mitigates CSRF)
  • Logout Handling: Show students that logging out requires BOTH destroying server session (req.session.destroy()) AND clearing client cookie (res.clearCookie('connect.sid')).
