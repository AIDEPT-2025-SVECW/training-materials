🛡️ Role-Based Authorization (RBAC) in Express.js

Continuation Guide: Restricting Route Access by User Roles (Admin, Instructor, Student)

🔗 GitHub Reference Project: stateful-app.js

1. Authorization vs Authentication Recap

Authentication (Who are you?): Handled in session_cookie_login.html via session login.
Authorization (What are you allowed to do?): Verifies whether the authenticated user possesses the required Role (e.g., admin, instructor, student) to access a specific resource.
Once your room key card proves you are a checked-in hotel guest (Authentication), you can enter your room. But if you try to open the Manager's Vault or Server Room (Admin Endpoint), the door lock checks your clearance (Authorization). If you are a standard guest, access is denied with HTTP 403 Forbidden!
Status Code Meaning When to Return
HTTP 401 Unauthorized User identity unknown / Not logged in Missing session cookie or invalid session
HTTP 403 Forbidden User identified, but lacks role permission Student trying to access Admin panel

2. Step-by-Step Authorization Setup

Step 1: Store User Role in Session on Login

When user logs in, ensure their role is stored in req.session.userRole:

// Inside POST /login endpoint
app.post('/login', (req, res) => {
    const { email, password } = req.body;
    const user = users.find(u => u.email === email && u.password === password);

    if (!user) {
        return res.status(401).json({ success: false, message: 'Invalid credentials' });
    }

    // Store user ID and ROLE in session
    req.session.userId = user.id;
    req.session.userRole = user.role; // e.g., 'admin', 'instructor', 'student'

    res.json({ success: true, message: 'Login successful!', role: user.role });
});

Step 2: Create Flexible Role Authorization Middleware

Create a higher-order middleware factory function authorize(...allowedRoles) that accepts allowed roles:

// Authorization Middleware Generator
const authorize = (...allowedRoles) => {
    return (req, res, next) => {
        // 1. Check if user is authenticated first
        if (!req.session || !req.session.userId) {
            return res.status(401).json({
                success: false,
                message: '401 Unauthorized: Please log in first.'
            });
        }

        // 2. Check if user's role is permitted
        if (!allowedRoles.includes(req.session.userRole)) {
            return res.status(403).json({
                success: false,
                message: `403 Forbidden: Role '${req.session.userRole}' is not allowed to access this resource!`
            });
        }

        next(); // User has required role! Proceed to route handler
    };
};

module.exports = authorize;

Step 3: Apply Authorization Middleware to Express Routes

Chain isAuthenticated and authorize(...) middleware on protected endpoints:

// 1. Student / Public Authenticated Route (Any logged in user)
app.get('/student/dashboard', isAuthenticated, (req, res) => {
    res.json({ message: 'Welcome Student Dashboard!' });
});

// 2. Instructor & Admin Only Route
app.get('/course/edit', isAuthenticated, authorize('admin', 'instructor'), (req, res) => {
    res.json({ message: 'Course Editor Access Granted!' });
});

// 3. Admin ONLY Route
app.get('/admin/system-settings', isAuthenticated, authorize('admin'), (req, res) => {
    res.json({ message: 'Welcome Admin Panel! Full System Access.' });
});

👨‍🏫 Instructor Teaching Notes
  • 401 vs 403 Clarity: Emphasize that 401 means "Unauthenticated (Login Required)", while 403 means "Authenticated, but Insufficient Permissions".
  • Middleware Chaining Order: Always place isAuthenticated BEFORE authorize(...) in route definitions to ensure req.session.userId exists!
