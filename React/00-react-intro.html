MODULE 00

ReactJS Introduction & Single Page Application (SPA) Architecture

Discover what React is, how Single Page Applications (SPAs) revolutionize user experience, the core LEGO component philosophy, and why React is preferred over traditional HTML, CSS, and Vanilla JavaScript.

🇮🇳 Real-World Analogy: LEGO Bricks & The Swiggy App Experience
Imagine building a toy Taj Mahal using LEGO bricks. Instead of molding one giant unbroken block of plastic, LEGO gives you small, reusable, independent bricks (Header brick, Button brick, Card brick). If one brick breaks, you swap only that single brick!

Traditional websites (Multi-Page Applications) are like ordering a new newspaper every time you want to read a single new headline. A React Single Page Application (SPA), like Swiggy or WhatsApp Web, loads the page background once and dynamically swaps food items or chat messages in-place without ever reloading the browser window!

1. What is React.js?

React.js (often called React) is a free, open-source, component-based front-end JavaScript library created by Jordan Walke at Meta (Facebook) in 2013. It is designed specifically for building interactive, fast, and scalable user interfaces (UIs).

  • Declarative UI: You describe what the UI should look like for a given state, and React handles updating the DOM to match it.
  • Component-Based: UIs are built out of small, self-contained, encapsulated code pieces called Components.
  • Focus on the View Layer: React represents the V in the traditional Model-View-Controller (MVC) software architecture.
  • Core Equation: UI = f(state) — User Interface is a pure function of application data state.

2. Is React a Library or a Framework? (Crucial Distinction)

Strictly speaking, React is a UI Library, NOT a Framework! Beginners often use these terms interchangeably, but the key distinction lies in Inversion of Control:

Feature / Criteria UI Library (e.g., React.js) Full Framework (e.g., Angular, Next.js, Spring)
Who is in Control? YOU are in control: You call React functions when you need to render UI components. The Framework is in control: Dictates application architecture and calls your code based on built-in lifecycle rules.
Scope Unopinionated and focused strictly on rendering the View Layer (V). Opinionated, complete end-to-end suite (Routing, HTTP client, Forms, State management included out of the box).
Architecture Flexibility High: You pick your own external tools (React Router for routing, Redux/Zustand for state, Axios for HTTP). Low: You must strictly follow the framework's file structures, conventions, and built-in abstractions.
Gradual Adoption Can be inserted into a single section/widget of a legacy web page without rewriting the whole site. Requires building the entire application around the framework architecture from scratch.

3. Single Page Applications (SPA) vs Multi-Page Applications (MPA)

Web architecture has evolved from traditional Multi-Page Applications to modern Single Page Applications:

Traditional Multi-Page Application (MPA)

In a traditional MPA (like old static websites or early PHP/Java JSP apps), clicking a link forces the browser to request a brand-new HTML document from the web server. The entire screen turns white, discards the current page memory, and re-renders all HTML, CSS, and scripts from scratch.

Modern Single Page Application (SPA)

A Single Page Application (SPA) loads a single index.html file on initial visit. When users navigate between sections or click buttons, JavaScript intercepts the action, fetches raw JSON data from server APIs via fetch() or axios, and dynamically updates only the affected parts of the web page without a full page refresh.

Feature Traditional Multi-Page App (MPA) React Single Page App (SPA)
Page Reloads Full browser page refresh on every click Zero full reloads (Seamless DOM updates)
HTML Delivery Server returns complete HTML for every route Server returns 1 single index.html; JS renders UI
User Experience Slower transitions with white screen flashes Instant, fluid desktop/mobile app-like experience
Data Transfer Transfers full HTML markup repeatedly Transfers minimal raw JSON data over background APIs
Real-World Examples Legacy banking sites, traditional blogs Swiggy, Gmail, Netflix, WhatsApp Web, Spotify

4. Core Idea of React: The LEGO Bricks Component Model

🧱 Component Architecture: Thinking in LEGO

In React, every piece of your web page is an independent, reusable Component — just like a LEGO brick! You create small components like <Navbar />, <SearchInput />, <ProductCard />, and <Footer />, then snap them together to build complete pages.

// 1. Independent LEGO Brick Component 1: SearchBar
function SearchBar() {
  return <input type="text" placeholder="Search Swiggy restaurants..." />;
}

// 2. Independent LEGO Brick Component 2: RestaurantCard
function RestaurantCard({ name, rating }) {
  return (
    <div className="card">
      <h3>🍱 {name}</h3>
      <span>⭐ {rating}</span>
    </div>
  );
}

// 3. Main Assembly Component: SwiggyApp (Combining the LEGO Bricks)
export default function SwiggyApp() {
  return (
    <main>
      <SearchBar />
      <RestaurantCard name="Empire Restaurant" rating="4.5" />
      <RestaurantCard name="Meghana Foods" rating="4.8" />
    </main>
  );
}

5. Why React? React vs Traditional HTML, CSS & Vanilla JS

Why do developers and companies choose React over writing plain HTML, CSS, and Vanilla JavaScript?

Comparison Criteria Traditional HTML + CSS + Vanilla JS React.js (UI Library)
DOM Manipulation Imperative: You manually query DOM elements (document.getElementById) and update text node by node. Declarative: You update application data state, and React automatically updates the DOM to match.
Performance Direct DOM updates are slow and trigger costly browser reflows and repaints. Uses Virtual DOM & Diffing Algorithm to batch and apply only minimal necessary DOM updates.
Code Reusability High duplication: Copy-pasting HTML blocks across multiple files. High reusability: Write a component once and render it anywhere with custom props.
State Synchronization Complex & error-prone: Manual synchronization between JS variables and HTML elements. Automatic: Reactive state (useState) ensures UI is always perfectly in sync with data.
Maintainability & Scale Spaghetti code: Monolithic JS files become unmaintainable as project grows. Modular architecture: Clear file boundaries, modular scope, and scalable team workflows.
⚠️ Key Takeaway for Beginners: React is NOT a replacement for HTML, CSS, and JS — it is built ON TOP of JavaScript! Learning JavaScript fundamentals (ES6 arrow functions, destructuring, .map(), modules) is the key to mastering React.
