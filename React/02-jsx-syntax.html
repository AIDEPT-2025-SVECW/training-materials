MODULE 02

JSX Syntax & Deep Dive

Explore JavaScript XML (JSX), embedding expressions with curly braces, JSX vs standard HTML differences, and Fragments.

🇮🇳 Indian Real-World Context: The Gujarati Thali
When ordering a Gujarati Thali, you receive multiple dishes (Dal, Kadhi, Rotli, Shaak). JSX Fragments (<></>) are like serving these dishes together on one banana leaf without forcing you to add extra plastic partition boxes (unnecessary wrapper <div> DOM nodes) on the table!

1. What is JSX?

JSX stands for JavaScript XML. It is a syntax extension for JavaScript that allows you to write HTML-like markup directly inside JavaScript files. Under the hood, Babel/Vite transpiles JSX into standard JavaScript React.createElement() function calls.

2. Why Use JSX?

Before React, web development artificially separated technologies: HTML for document structure, JS for behavior, and CSS for styling. React realized that rendering logic is inherently coupled with UI logic (event handling, state management, and data formatting). JSX offers several major advantages:

  • Component Cohesion: UI structure and logic live together in a self-contained component file.
  • Full Power of JavaScript: Anything JavaScript can evaluate (loops, array methods like .map(), ternary operators) can be embedded directly in your UI using { }.
  • Built-in XSS Security: React automatically escapes strings rendered inside JSX expressions before displaying them, effectively preventing Cross-Site Scripting (XSS) security vulnerabilities.
  • Developer Experience: Visual structure looks like HTML, making UI code readable and intuitive, with rich IDE autocomplete and linting support.

3. Key Differences: JS vs JSX vs TS vs TSX

It's easy to get confused by file extensions in modern frontend frameworks. Here is how standard JavaScript, JSX, TypeScript, and TSX compare:

Format & Extension Full Form HTML Markup in Code? Static Type Checking? Direct Browser Execution? Transpiled Output
JS (.js) Standard JavaScript ❌ No ❌ Dynamic (Runtime) ✅ Yes (Natively supported) Executes directly in JS engines
JSX (.jsx) JavaScript XML ✅ Yes (HTML tags allowed) ❌ Dynamic (Runtime) ❌ No (Needs Babel / Vite) Compiles to React.createElement()
TS (.ts) TypeScript ❌ No ✅ Static (Compile-time) ❌ No (Needs tsc) Compiles to plain JavaScript
TSX (.tsx) TypeScript XML ✅ Yes (HTML tags allowed) ✅ Static (Compile-time) ❌ No (Needs Vite/Babel) Compiles to Typed React JavaScript

// Example: Dynamic Inline Style Object in JSX
const cardStyle = {
  backgroundColor: isSelected ? '#e0e7ff' : '#ffffff',
  borderRadius: 12,           // Auto-appends 'px' -> 12px
  padding: '1.5rem',
  boxShadow: '0 4px 6px rgba(0,0,0,0.1)',
  zIndex: 10,                 // Unitless number preserved
  '--accent-color': '#4f46e5' // CSS custom property
};

function StyledBox() {
  return <div style={cardStyle} className="card-container">Dynamic Box</div>;
}

6. Embedding Expressions in JSX with { }

You can embed any valid JavaScript expression (variables, function calls, math, ternary statements) inside JSX by wrapping it in curly braces { }:

function DishCard() {
  const dishName = "Paneer Tikka";
  const price = 240;
  const discountPercent = 10;
  
  const calculateFinalPrice = () => price - (price * discountPercent / 100);

  return (
    <div className="menu-card">
      <h3>🍛 {dishName.toUpperCase()}</h3>
      <p>Original Price: ₹{price}</p>
      <p><strong>Offer Price: ₹{calculateFinalPrice()}</strong></p>
    </div>
  );
}

7. JSX Fragments (<React.Fragment> / <></>)

A React component must return a single root element. If you need to return multiple adjacent sibling elements without adding an extra wrapper <div> to the browser DOM, use a Fragment:

// Using short syntax Fragment
function MenuItems() {
  return (
    <>
      <h2>Starters</h2>
      <p>Hara Bhara Kebab - ₹180</p>
    </>
  );
}
⚠️ Developer Warning: Objects cannot be rendered directly inside curly braces { { name: 'Rahul' } }. This throws a "Objects are not valid as a React child" TypeError! Extract the primitive property (e.g., { user.name }).
