MODULE 12

Updating the Screen & Immutability

Master the Event → State Update → Re-render cycle, functional state updates setCount(prev => prev + 1), and React 18 automatic batching.

🇮🇳 Indian Real-World Context: Chai Stall Rush Hour Queue
During 9 AM office rush hour at a Tapri Chai Stall, multiple customers order simultaneously. If the cashier updates the token counter using stale state, orders get overwritten! Calling setToken(prevToken => prevToken + 1) ensures queue tokens increment safely based on the latest token state.

1. The Re-render Lifecycle Loop

  1. User Interaction: User clicks a button or types in an input.
  2. State Dispatch: Event handler calls state setter (e.g., setToken(...)).
  3. Component Re-render: React calls the component function again with updated state values.
  4. DOM Reconciliation: React updates the real DOM efficiently.

2. Functional State Updates vs Direct Value Passing

When state updates rely on the previous state value, always pass a callback function to the state updater:

import React, { useState } from 'react';

export default function ChaiQueueCounter() {
  const [tokensIssued, setTokensIssued] = useState(100);

  // ❌ Problematic: Multiple rapid state calls overwrite each other
  const handleRushHourBad = () => {
    setTokensIssued(tokensIssued + 1); // 100 + 1
    setTokensIssued(tokensIssued + 1); // 100 + 1 (stale state!)
  };

  // ✅ Best Practice: Functional updater queues updates correctly
  const handleRushHourGood = () => {
    setTokensIssued(prev => prev + 1); // 100 -> 101
    setTokensIssued(prev => prev + 1); // 101 -> 102
  };

  return (
    <div className="counter-box">
      <h3>☕ Current Chai Token: #{tokensIssued}</h3>
      <button onClick={handleRushHourGood}>+ Issue 2 Rush Hour Tokens</button>
    </div>
  );
}
⚠️ Automatic Batching in React 18: React 18 automatically batches multiple state updates occurring within async promises, setTimeout, or native event handlers into a single re-render pass for optimal performance.
