A short field guide

Every API call is correspondence

A REST API works like sending a letter. The URL is the address, the HTTP method is the instruction stamped on the envelope, and the body is what's written inside. This guide walks through the fundamentals, why the method you choose matters, and lets you send a real request with Postman-style tools — right here.

01

What a REST API actually is

REST (Representational State Transfer) is a set of conventions for how a client and a server talk to each other over HTTP. A client doesn't ask a server to "run a function" — it asks for, or acts on, a resource: a letter, a user, an order, a comment. Every resource lives at its own address, and the server replies with a representation of it, almost always as JSON.

Resource
The letter sitting in a mailbox — a user, a post, an order.
URL
The address on the envelope — where that specific resource lives.
HTTP method
The instruction stamped on it — read it, send a new one, replace it, throw it out.
Response
The reply that comes back — a status code plus, usually, a JSON body.

Two conventions make this predictable across every REST API you'll ever use: the server keeps no memory of previous requests (statelessness — each letter must stand on its own), and every resource is handled through the same small set of verbs, no matter what the resource is. That second point is the whole reason HTTP methods matter as much as they do.

02

HTTP methods, and why the choice isn't cosmetic

Picking the right method isn't a style preference — it tells every browser, cache, proxy, and teammate reading your API exactly what a request is allowed to do before it even runs. A GET is safe to prefetch or retry endlessly; a POST is not. Get this wrong and you'll get double-charged orders, browsers that refuse to cache things they safely could, and APIs that are miserable to reason about.

GET

Fetch a representation of a resource. Reading it should never change anything.

Safe = doesn't change server state. Idempotent = calling it once or ten times leaves the resource in the same state.

03

Postman, briefly

Postman is a desk for building and sending HTTP requests without writing any client code first. You pick a method, type an address, fill in a body if the request needs one, and send it — then read exactly what came back. It's usually the first place developers try out an API before wiring it into an application.
