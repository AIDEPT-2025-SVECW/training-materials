🔒 HTTP vs HTTPS & Web Security

Understanding Encryption, TLS/SSL Handshake, Integrity, and Port Security

1. What is HTTP vs HTTPS?

⚠️ HTTP (HyperText Transfer Protocol)

Transmits data in PLAIN TEXT across the network.

  • Default Port: 80
  • Security: None (Unencrypted)
  • Threats: Eavesdropping, Packet Sniffing, Man-in-the-Middle (MitM) attacks
  • URL Scheme: http://example.com

🛡️ HTTPS (HTTP Secure over TLS/SSL)

Encrypts data using TLS (Transport Layer Security) / SSL.

  • Default Port: 443
  • Security: End-to-End Encryption + Data Integrity + Server Authentication
  • Protection: Prevents eavesdropping and tampering
  • URL Scheme: https://example.com

🤝 How HTTPS Works: The TLS/SSL Handshake

Before any HTTP data is transmitted, the client and server perform a cryptographic handshake to establish a secure connection:

Step 1: Client Hello
Client sends supported TLS version, cipher suites, and a random number (`ClientRandom`).
Step 2: Server Hello & Certificate
Server chooses cipher suite, sends its SSL Certificate (containing Public Key and CA Signature) + `ServerRandom`.
Step 3: Verification & Key Exchange
Client verifies the Certificate with a trusted Certificate Authority (CA), generates a `Premaster Secret`, encrypts it with Server's Public Key, and sends it.
Step 4: Session Key Generation
Both client & server use the secret to generate identical Symmetric Session Keys.
Step 5: Secure Symmetric Session Active 🔒
All subsequent HTTP requests & responses are encrypted symmetrically at blazing speed!
