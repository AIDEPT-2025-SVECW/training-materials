1. IP Addresses, DNS & Network Ports

Just like sending a physical letter to a friend requires a street address and an apartment door number, sending data across the internet relies on three fundamental concepts:

📮 1. IP Address (The Street Address)

Every device connected to the internet receives a unique numerical identifier called an IP Address.

• IPv4: 4 numbers separated by dots (e.g. 172.217.14.206).
• IPv6: 128-bit hexadecimal address created to solve IPv4 address exhaustion.

📖 2. DNS (The Internet's Phonebook)

Humans remember names like foodordering.com, but servers only understand numbers like 142.250.190.46.

Domain Name System (DNS) translates human-friendly URLs into machine-readable IP addresses in milliseconds!

🏢

Master Analogy for Freshers: Apartment Building & Door Numbers

Imagine a huge apartment building located at 100 Tech Park Way (IP Address). Inside the building, there are different departments:

• Door #80 / #443 (HTTP/HTTPS): The Reception Counter for public website visitors.
• Door #3306 (MySQL Database): The Secure Vault storing user passwords & orders.
• Door #8080 (Spring Boot API): The Kitchen preparing order data.

Network Ports are these specific apartment door numbers on a server!

Standard Well-Known Network Ports:

Port Number Protocol / Service Common Usage
80 HTTP Unencrypted web traffic (plaintext)
443 HTTPS Secure TLS/SSL encrypted web traffic
22 SSH Secure remote terminal access to Linux servers
3306 MySQL / MariaDB Database server connections
5432 PostgreSQL Relational database endpoint
8080 / 3000 Application Backend Spring Boot Java API / Node.js Express server

2. Transport Layer: TCP vs UDP

Data sent over the internet is broken down into small packets. How those packets are delivered depends on the transport protocol chosen:

📦 TCP (Transmission Control Protocol)

Reliable & Connection-Oriented. Guarantees that every single packet arrives in exact order without loss. Uses a 3-Way Handshake to establish connection first.

Best For: Web Browsing (HTTP), REST APIs, Email, Database queries, File Transfers (where losing 1 byte corrupts the data).

🚀 UDP (User Datagram Protocol)

Ultra-Fast & Connectionless. Sends packets immediately without a handshake or acknowledgment. If a packet gets lost in transit, it is simply dropped.

Best For: Live Video Streaming (Zoom, YouTube Live), Online Multiplayer Gaming, Voice over IP (VoIP), DNS queries.

3. Firewalls, Security Groups & End-to-End Request Path

🛡️ Firewalls & Cloud Security Groups

Acts as a digital bouncer at the server entrance. Configured with Ingress (Incoming) and Egress (Outgoing) rules:

• ALLOW: Port 443 (HTTPS) from any IP (0.0.0.0/0).
• BLOCK: Port 3306 (Database) from the public internet (only allow internal App Server IPs!).

🗺️ The End-to-End Request Journey

When a user orders food on their phone app, the HTTP request follows a precise sequence:

User App ➔ DNS Lookup ➔ Firewall Gate ➔ Load Balancer ➔ Backend App (Port 8080) ➔ Database (Port 3306).

5. Fresher Assessment Scenarios

In technical assessments, students are often asked to choose the best engineering decision rather than repeat a definition. Try these examples.

Scenario 1: One server fails Use a load balancer with health checks and route traffic to healthy instances.
Scenario 2: Website is slow Check DNS, network latency, server load, database performance and application logs.
Scenario 3: Secure login Use HTTPS on port 443 and protect sensitive data in transit.
Scenario 4: Only trusted traffic Configure firewall or security-group rules using least privilege.
Scenario 5: Reliable API request TCP is generally suitable when ordered and reliable delivery is important.
Scenario 6: Live voice or gaming UDP may be preferred when low delay matters more than retransmitting every packet.

6. Networking Revision Checklist

Before the assessment, a student should be able to answer “what, why and when” for each item.

  • What is an IP address? Difference between public and private IP addresses.
  • What does DNS do? What happens when DNS resolution fails?
  • What is a port? Know common examples: 80, 443, 22 and 3306.
  • Why is TCP used for many web and API requests?
  • When might UDP be useful?
  • What is the difference between HTTP and HTTPS?
  • What does a firewall or security group allow or block?
  • Why do we use a load balancer?
  • Can you explain the complete path from browser to backend and database?
