Topic 09

Agile Ceremonies & Sequential Process

Mastering the step-by-step Sprint lifecycle, core ceremonies, and key terms (Sprint, Backlog, Grooming, DoD, Retrospective).

Sequential Sprint Execution Flow

Agile teams work in fixed timeboxes called Sprints (typically 2 weeks). Here is the sequential process flow from initial requirement to working increment:

1

📋 1. Product Backlog Creation Artifact

The single source of truth: a prioritized master list of all features, enhancements, user stories, and bug fixes created and owned by the Product Owner.

TastyDash Example: Backlog contains 50 items (Search food, Filter by vegan, Add credit card payment, Track driver GPS).
2

🔍 2. Backlog Refinement / Grooming Ceremony

PO and Dev Team meet mid-sprint to clarify upcoming user stories, write acceptance criteria, remove ambiguity, and estimate effort using Story Points (Fibonacci).

TastyDash Example: Team estimates US-102: Add Stripe Checkout at 8 Story Points.
3

🎯 3. Sprint Planning Meeting Ceremony

Held on Day 1 of the 2-week Sprint. PO presents top priority items. Dev team selects stories based on team capacity and commits to the Sprint Goal & Sprint Backlog.

TastyDash Example: Sprint 3 commitment = 30 Story Points (Checkout API + Cart UI + Order Summary).
4

🏃 4. Sprint Execution & Daily Standup Daily Ceremony

15-minute daily standup meeting where devs sync progress answering 3 core questions: 1) What did I do yesterday? 2) What will I do today? 3) Are there any blockers?

TastyDash Example: Backend dev reports Stripe webhook API is done; frontend dev starts connecting React payment form.
5

🎉 5. Sprint Review / Product Demo Ceremony

Held on the last day of the sprint. Dev team demonstrates working software live to the Product Owner and Business Stakeholders to get immediate feedback.

TastyDash Example: Devs demo ordering a pizza and paying via credit card on a live staging environment.
6

🔄 6. Sprint Retrospective ("Retro") Ceremony

Internal team reflection meeting to continuously improve engineering process. Evaluates 3 questions: 1) What went well? 2) What went wrong? 3) Action items for next sprint.

TastyDash Example: Retro Action Item = Automate Docker deployment tests to avoid manual deployment delays.

✅ Definition of Done (DoD) Checklist

A shared quality contract ensuring code is ready for production before marking a User Story as complete:

  • ✔ Clean code written & peer reviewed via GitHub Pull Request
  • ✔ All automated JUnit & React unit tests pass (100% build pass)
  • ✔ Acceptance criteria verified by QA engineer
  • ✔ Deployed to Staging cloud environment without bugs
  • ✔ Product Owner accepts and signs off on the feature demo
